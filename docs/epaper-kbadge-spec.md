## 1. 项目背景

KFlow 是一个 Django 5.2 开发的产品官网 + 社区平台，现有能力包括账号体系、K 积分账本、数字兑换码商店（K 士多）、产品与版本下载（支持 HTTP Range 续传与 SHA-256 校验）、社区（论坛 / 碎碎念 / 通知 / 等级成就）、以及 AI 助手「小 K」。

本项目的目标不是做一块通用墨水屏，而是做一块**绑定到 KFlow 账号**的桌面终端：它显示的每个像素都来自用户自己的账号数据，它消耗的每次同步都走已有的鉴权与计费链路。

首版刻意剥离了语音、触摸、彩屏，只保留「看一眼就够」的信息，把工程风险压到最低。

## 2. 产品定义

### 2.1 形态

- 卡片式桌面 / 挂壁两用，横向显示
- 参考外形 96 × 52 × 10 mm（依最终外壳调整）
- 2.9 英寸黑白红三色墨水屏，屏占比优先
- 正面下方 1 个物理按键（复位 / 手动刷新）
- 背面磁吸片 + 隐藏式支架孔
- Type-C 口（充电 + 烧录）
- 无喇叭、无麦克风、无触摸

### 2.2 显示内容

分 4 屏，按键短按切换，默认停在主屏：

| 屏 | 内容 |
|---|---|
| 主屏 | 小 K 头像、用户名、等级徽章、K 积分余额 |
| 屏 2 | 最近 3 条碎碎念标题 + 相对时间 |
| 屏 3 | 未读通知数、成就解锁进度 |
| 屏 4 | 设备信息：固件版本、电量、WiFi SSID、上次同步时间、绑定码后 4 位 |

### 2.3 交互

| 操作 | 行为 |
|---|---|
| 短按（< 800ms） | 切换下一屏；若当前屏数据超过同步周期，顺带触发一次拉取 |
| 长按（> 3s） | 强制全量同步 + 重绘 |
| 长按（> 8s） | 清除 WiFi 配置，进入配网模式（AP 热点） |
| 双击 | 显示屏 4（设备信息），10 秒后回到主屏 |

### 2.4 刷新策略（关键约束）

三色墨水屏**一次全局刷新约 15 秒**，这是产品设计的第一约束，不能对抗只能顺应：

- 屏幕内容**按需刷新**，不是按时间刷新。内容没变就不刷。
- 联网拉数据可以比刷新频繁。推荐每小时联网一次，只有 diff 命中才重绘。
- 刷新过程中必须等 `BUSY` 释放才能发下一条指令，否则花屏。
- 交互反馈不能依赖屏幕——按键按下后的 15 秒里屏幕是「僵死」的，需用 LED 或蜂鸣器给反馈（首版可用板载 LED 呼吸）。

## 4. 引脚定义

### 4.1 屏幕接口（8 pin）

模块丝印顺序可能因批次不同而变化，**必须按丝印接线，不能按物理顺序**。

| 模块引脚 | 功能 | ESP32-C3 | 类型 | 说明 |
|---|---|---|---|---|
| VCC | 电源 | 3V3 | 电源 | **严禁接 5V**，面板为 3.3V 器件 |
| GND | 地 | GND | 电源 | 共地，不可省 |
| DIN | SPI MOSI | GPIO6 | 输出 | 数据 |
| CLK | SPI SCK | GPIO4 | 输出 | 时钟 |
| CS | 片选 | GPIO7 | 输出 | 低有效 |
| DC | 数据/命令 | GPIO5 | 输出 | 高=数据，低=命令 |
| RST | 复位 | GPIO3 | 输出 | 低有效 |
| BUSY | 忙信号 | GPIO10 | 输入 | 低=忙，**必须接** |

引脚可改，只要满足两条：

1. 避开 ESP32-C3 的启动 strapping 脚：**GPIO2、GPIO8、GPIO9**（GPIO9 是 BOOT）。
2. 避开 USB 下载口占用的 GPIO18/GPIO19（若用原生 USB）。

### 4.2 其他

| 信号 | GPIO | 类型 | 说明 |
|---|---|---|---|
| 按键 | GPIO1 | 输入 | 低有效，内部上拉，外部 100nF 消抖 |
| 电池电压采样 | GPIO0 | ADC1_CH0 | 分压 1M / 1M + 100nF，静态电流 1.85µA |
| 板载 LED | GPIO21 | 输出 | 高亮，串 1k；占用 UART0 TXD，调试改走原生 USB |
| USB D− / D+ | GPIO18 / GPIO19 | — | 原生 USB，烧录与串口复用 |

> **引脚冲突说明**：C3 上除 strapping 脚（2/8/9）与 UART0（20/21）外，可用 IO 已被本方案占满。
> LED 放 GPIO21 会让 CH343 那类 UART 桥无法工作；若必须保留串口日志，
> 把 LED 移到 GPIO20（只牺牲 UART 接收），或干脆省掉 LED 用屏幕内容代替。

> **注意**：ESP32-C3 的 ADC 只在 GPIO0–GPIO4（ADC1）与 GPIO5（ADC2）上可用。
> 本方案把 GPIO5 给了屏幕 DC，因此电池采样只能落在 GPIO0–GPIO4 之间；
> GPIO2/3/4 已被 strapping 或 SPI 占用，最终选 GPIO0。
> 若后续需要第二个模拟通道（如温度传感器），需重新分配引脚。

> **待确认**：是否需要电量百分比。若只做「低电告警」，可省掉分压电路，GPIO0 释放。

### 4.3 硬件设计红线

1. **VCC 只接 3V3**。GxEPD2 作者原文：panel 是 3.3V 供电且数据线也必须是 3.3V，5V 直连会损坏。
2. **BUSY 不能悬空**。悬空表现为「一直白屏」，是最常见的故障。
3. **刷新期间不要断 VCC**。三色屏刷新 15s，中途断电会留下残影且可能损坏面板。
4. **屏排线不要折**。FPC 折一次就可能断线，结构设计要给排线留缓冲弯。
5. **深睡时切断 EPD 电源**，用 PMOS，控制脚默认上拉（断电）。

## 5. 固件方案

### 5.1 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | PlatformIO + Arduino-ESP32（或纯 ESP-IDF） | 首版用 Arduino 框架，迭代快 |
| 显示驱动 | **GxEPD2**（`GxEPD2_3C`） | 事实标准，支持 296×128 三色 |
| 图形库 | Adafruit_GFX | GxEPD2 依赖 |
| 中文字库 | 自建点阵子集（见 5.5） | 不要用 GFX 内置 ASCII 字体 |
| 网络 | WiFiClientSecure + HTTPClient | 走 HTTPS |
| 存储 | NVS（token / WiFi / 配置）+ LittleFS（字库、位图资源） | |

> ⚠️ **许可证问题（必须由对接方明确答复）**
> GxEPD2 **是 GPL-3.0**。若整机固件闭源分发，GPL-3.0 会要求公开固件源码。
> 三个可选路径，请在报价前确定：
>
> | 路径 | 代价 | 结论 |
> |---|---|---|
> | A. 接受 GPL，固件开源 | 无额外开发量；对社区产品可能是加分项 | 最快，但商业上需接受 |
> | B. 自研 SSD1680 / IL0373 驱动 | 约 300–500 行 SPI 命令封装，3–5 人日 | 彻底自由，推荐量产走这条 |
> | C. 换 Adafruit_EPD（MIT） | 型号覆盖需确认，可能不支持三色 296×128 | 折中，先验证覆盖度 |
>
> 首版验证阶段可以先用 GxEPD2 跑通，量产前必须落定。

### 5.2 软件分层

```
app/            业务：页面渲染、按键、同步调度
  ui/           布局与绘制（纯函数，输入数据输出绘制指令）
  sync/         联网拉取、diff 判断、失败重试
  power/        深睡与唤醒管理
drivers/        EPD 驱动封装（可替换，隔离 GPL 依赖）
bsp/            引脚定义、LED、按键、ADC
assets/         字库、图标位图
```

驱动层要**抽象成接口**（`init / drawFull / hibernate`），这样 B 路径替换 GxEPD2 时上层代码零改动。

### 5.3 启动流程

```
上电 / 定时唤醒
   │
   ├─ 读 NVS：token 存在？
   │    否 → 进入配网模式（AP + 网页配置），显示配网页二维码
   │    是 ↓
   ├─ 连 WiFi（超时 15s，失败退避重试 2 次）
   │    失败 → 保留旧画面，角落标记「离线」，进深睡
   ├─ GET /api/devices/me
   │    401 → token 失效，进入重新绑定流程
   │    200 → 拿到数据 ↓
   ├─ 与上次缓存 diff：有变化？
   │    否 → 不刷新，直接深睡
   │    是 → 渲染 → 全刷（等 BUSY）→ hibernate
   ├─ POST /api/devices/heartbeat（电量、信号、固件版本）
   └─ 深睡（默认 60 分钟）
```

### 5.4 低功耗

刷新前后必须严格按此顺序：

```cpp
display.hibernate();          // 屏控制器进低功耗
digitalWrite(EPD_PWR, HIGH);  // PMOS 关断，切断屏模块供电
WiFi.disconnect(true);
WiFi.mode(WIFI_OFF);
esp_sleep_enable_timer_wakeup(interval_us);
esp_deep_sleep_start();
```

注意事项：

- `display.hibernate()` 必须在断电之前，否则控制器状态未保存，下次唤醒可能白屏。
- 唤醒后 PMOS 重新上电要给 100ms 稳定时间再 `init()`。
- 深度睡眠期间 GPIO 保持状态，按键唤醒用 `esp_sleep_enable_ext0_wakeup` 或 GPIO 唤醒。

### 5.5 中文显示（隐藏难点，务必提前排期）

墨水屏只有 2 级灰（黑 / 白 / 红），不能抗锯齿也不能灰阶渲染，中文字形必须**1-bit 点阵**，否则边缘发虚、红黑混色。

三个方案：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A（推荐）** | Python 脚本把需要的字（约 800–1500 个常用字 + 数字符号）渲染成 1-bit 点阵，生成 `.c` 数组编译进固件 | 体积可控（12px 单字 24B，1500 字约 36KB），渲染最快 | 生僻字缺失，需维护字表 |
| B | 用 `U8g2_for_Adafruit_GFX` + 文泉驿点阵字库 | 现成 | 字库体积大（>500KB），且字体风格与品牌不搭 |
| C | 换成矢量渲染（FreeType / LVGL） | 任意字号 | 内存与 Flash 开销大，C3 吃力，不推荐 |

字表来源：从社区实际内容里统计高频字，比盲选 3500 常用字省一半空间。

> **待确认**：用户名是否允许生僻字。若允许，方案 A 需补充「缺字回退为拼音首字母」策略。

### 5.6 OTA

复用平台现有能力，不新建分发通道：

1. 设备请求 `GET /api/devices/ota/latest?hw=kbadge&fw=0.3.1`
2. 服务端返回 `{version, url, size, sha256}`，`url` 指向平台已有的下载接口（支持 HTTP Range）
3. 设备用 HTTP Range 断点续传下载到备用分区，**边下边算 SHA-256**
4. 校验通过 → 切分区 → 重启；校验失败 → 保留旧固件，上报失败原因
5. 上报 `POST /api/devices/heartbeat` 带 `fw_version`，后台可见升级率

关键约束：

- Flash 4MB，分区方案：`nvs(20K) / otadata(8K) / app0(1.4M) / app1(1.4M) / littlefs(1M)`
- **固件必须 < 1.3MB**，中文点阵字库放 LittleFS 而非编译进 app
- 升级期间断电不能变砖：分区切换是原子的，靠 `otadata` 保证
- 不允许静默升级到不兼容版本，协议里带 `min_fw` 兼容位

## 6. 通信协议

### 6.1 通用约定

- 传输：HTTPS（本地调试可 HTTP）
- 编码：`application/json; charset=utf-8`
- 鉴权：`Authorization: Bearer <device_token>`（除 `bind` 外全部需要）
- 时间：ISO-8601 字符串，UTC 带偏移，例 `2026-10-23T15:30:00+08:00`
- 成功响应统一含 `"ok": true`
- 失败响应统一为 `{"error": "<机器可读的错误码>", "message": "<中文说明>"}`
- 所有写操作必须幂等，设备可能因网络问题重发

### 6.2 绑定

```
POST /api/devices/bind
Content-Type: application/json

{
  "code": "K7F2M9QX",        // 8 位绑定码，大小写不敏感，去除连字符
  "device_uid": "A0B1C2D3E4F5",  // 设备 MAC，大写无冒号
  "hw_model": "kbadge",
  "hw_version": "1.0",
  "fw_version": "0.1.0"
}
```

成功 `200`：

```json
{
  "ok": true,
  "device_token": "dvt_9f3a...64位随机串",
  "user": {"username": "kieran", "display_name": "Kieran", "level": 3},
  "points": 1280,
  "sync_interval": 3600
}
```

失败：

| HTTP | error | 场景 |
|---|---|---|
| 400 | `invalid_code` | 格式不对 |
| 404 | `code_not_found` | 码不存在 |
| 409 | `code_used` | 已被使用 |
| 410 | `code_expired` | 已过期（默认 7 天） |
| 409 | `device_already_bound` | 该设备已绑定其他账号，需先在网页解绑 |

规则：

- 绑定码**一次性**，服务端只存 `sha256(code)`，绑定成功即刻作废
- 同一 `device_uid` 只能绑一个账号；换绑必须先解绑
- `device_token` 长期有效，可轮换；服务端只存 hash

### 6.3 拉取状态

```
GET /api/devices/me
Authorization: Bearer <device_token>
```

`200`：

```json
{
  "ok": true,
  "server_time": "2026-10-23T23:40:00+08:00",
  "user": {
    "username": "kieran",
    "display_name": "Kieran",
    "level": 3,
    "level_title": "L3 常驻作者",
    "avatar_seed": "kieren-01"
  },
  "points": 1280,
  "unread_notifications": 5,
  "achievements": {"unlocked": 7, "total": 24},
  "murmurs": [
    {"id": "…", "excerpt": "今天把墨水屏点亮了", "ago": "2 小时前"},
    {"id": "…", "excerpt": "K 士多上了新的兑换码", "ago": "昨天"}
  ],
  "device": {"bound": true, "fw_version": "0.1.0", "server_fw_latest": "0.3.1"},
  "refresh_hint": 3600
}
```

`401` → 清 token，进入重新绑定。

### 6.4 心跳

```
POST /api/devices/heartbeat
Authorization: Bearer <device_token>

{
  "battery_mv": 3980,
  "battery_pct": 76,
  "rssi": -62,
  "fw_version": "0.1.0",
```

`200`：`{"ok": true, "server_time": "...", "next_wake_s": 3600}`

服务端据此更新设备在线状态、电量曲线、固件版本分布。

### 6.5 固件查询

```
GET /api/devices/ota/latest?hw=kbadge&fw=0.1.0
Authorization: Bearer <device_token>
```

有新版：

```json
{
  "ok": true,
  "update": true,
  "version": "0.3.1",
  "url": "https://kflow.example/api/devices/ota/download/42",
  "size": 892416,
  "sha256": "a73daf3465eac4907277fbdb1494d926d56f9f338e9cafa707276498ee563982",
```

`sha256` 字段沿用平台 `products.file_sha256` 的语义，设备端必须校验通过才允许切换分区。

## 7. 屏幕 UI 规范

### 7.1 画布

- 逻辑画布 **296 × 128 px**，原点左上，横屏
- 安全边距 8px，内容区 280 × 112
- 1px 线宽，不画 1px 圆角（点阵屏上会糊）

### 7.2 字体

| 用途 | 字号 | 字重 |
|---|---|---|
| 用户名 | 16px | 常规 |
| 等级 / 积分 | 12px | 常规 |
| 碎碎念正文 | 12px | 常规 |
| 时间 / 状态 | 10px | 常规（最小可读字号） |
| 数字（积分） | 20px | 粗 |

不允许抗锯齿，不允许小于 10px 的字。

### 7.3 三色使用规则

- **红色每屏最多 1 处**，用于等级角标或未读红点，面积不超过屏面 3%
- 大面积红会让刷新时间更长，且廉价感强
- 黑色只用于正文与分隔线；白色（未上色）为底
- 头像用 1-bit 抖动（Bayer 4×4）转黑白，不要尝试灰度

### 7.4 主屏布局

| 区域 | 坐标 (x, y, w, h) | 内容 |
|---|---|---|
| 状态条 | 0, 0, 296, 16 | 左 `KFlow` 12px；右 电量 + WiFi 图标 |
| 分隔线 | 0, 16, 296, 1 | 黑 |
| 头像 | 8, 24, 64, 72 | 1-bit 抖动，圆角由图层遮罩实现 |
| 用户名 | 80, 24, 208, 18 | 16px，超长省略号 |
| 等级 + 积分 | 80, 44, 208, 16 | `L3 常驻作者` + `1280 K` |
| 分隔线 | 80, 64, 208, 1 | 黑，粗 1px |
| 最近内容 | 80, 70, 208, 38 | 12px，最多 2 行，行高 18 |
| 底栏 | 0, 112, 296, 16 | 右对齐 `23:40 同步` 10px |

> **待确认**：头像来源。建议服务端直接返回 64×72 的 1-bit 位图（Base64 或独立 URL），设备端不做图片处理，避免在 C3 上跑解码。

### 7.5 图标

全部用 1-bit 位图，尺寸 8×8 / 12×12 / 16×16，打包进 LittleFS。禁止用字体图标（三色屏上会糊成一团）。

## 8. 功耗预算

假设：1000mAh 电芯，可用容量按 70% 计（700mAh），每小时联网一次，每天实际刷新 4 次。

| 动作 | 电流 | 时长 | 单次耗电 |
|---|---|---|---|
| 唤醒 + WiFi 连接 | ~160mA | 4s | 0.178 mAh |
| HTTPS 请求（含 TLS 握手） | ~120mA | 2s | 0.067 mAh |
| 三色全刷 | ~26mA | 15s | 0.108 mAh |
| 深睡 | ~0.02mA（含 PMOS 断电） | 剩余时间 | ~0.02 mAh/h |

日耗电 ≈ 24 × (0.178 + 0.067) + 4 × 0.108 + 24 × 0.02 ≈ 6.8 mAh

**理论续航 ≈ 700 / 6.8 ≈ 100 天**

保守对外标注 **≥ 60 天**（考虑低温、WiFi 弱信号重试、电池衰减）。

> 若首版实测低于 45 天，优先排查：① EPD 深睡是否真的断电；② WiFi 是否真的关闭；③ 是否有 GPIO 漏电。

## 10. 合规

### 10.1 SRRC 型号核准（强制）

- 任何带 WiFi 发射、面向国内销售的产品必须取得无线电发射设备型号核准，机身或包装标注 **CMIIT ID**
- 使用已认证模组（ESP32-C3-MINI-1）**只能减免测试项，整机仍需单独申请、拿自己的核准号**，不能借用模组编号
- 官方申请本身不收费，成本主要是授权实验室测试费（需询价）
- 改天线结构、改发射功率、增减无线功能，均视为新机型，需重新认证
- 证书有效期 5 年

### 10.2 销售备案

生产商对外销售（含网店）需另行办理销售备案，与型号核准是两件独立事项。

### 10.3 其他

- **锂电池运输**：含电池整机走快递需陆运，部分承运方要求电池 UN38.3 报告，发货前与快递确认
- **3C**：是否适用取决于产品类别与是否随附电源适配器，需按目录确认
- **出口**：如涉及海外销售，需另行评估 CE / FCC

> **待确认**：首版是「只送不卖」还是「对外销售」。这决定 SRRC 是否必须先做完才能出货。建议首版 10 台先做「送测 / 送用户」，同步启动认证。
