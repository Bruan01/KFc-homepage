## 1. 背景与定位

### 1.1 背景

现有首页（`/`，"KFlow | Product Delivery Hub"）以产品下载、更新动态、案例展示为主，社区论坛（`/forum`）、积分（`/points`）、K 士多商店（`/store`）作为附属入口存在，流量结构以"看产品"为主，缺少用户停留、互动与持续回访的理由。

### 1.2 新定位（一句话）

> **把首页改造成一个 Vibecoding 社区：晒作品、看排行、学教程、赚积分、换好物。**

- **晒作品**：用户发帖展示自己的 vibecoding 项目（一段话介绍 + 图片 + 项目链接）。
- **看排行**：全网 vibecoding 项目排行榜 + 站内作品排行榜，提供"逛"的理由。
- **学教程**：简单上手的 vibecoding 教程与开发范式，降低新用户门槛。
- **赚积分**：发帖、点赞、评论等活跃行为获得积分。
- **换好物**：积分在 kflowstore 兑换商品，用户也可以上架自己的东西。

### 1.3 目标用户

| 用户群 | 描述 | 核心诉求 |
| --- | --- | --- |
| vibecoding 玩家 | 用 Cursor / Claude Code 等工具做过项目的开发者、爱好者 | 晒作品被看见、获得反馈 |
| 旁观者 / 新手 | 想入门但没做过完整项目的人 | 找到可模仿的项目和教程 |
| 围观用户 | 只逛不发的内容消费者 | 看排行榜、看热门作品 |

### 1.4 成功指标

| 类型 | 指标 | 定义 |
| --- | --- | --- |
| 北极星 | 周活跃发帖用户数 | 每周至少发 1 帖或 1 评论的去重用户 |
| 内容 | 周新增帖子数 / 帖均互动数 | 互动 = 点赞 + 评论 |
| 激励 | 积分流转率 | 消耗积分 ÷ 获取积分（健康区间 30%~70%） |
| 商业 | 加热使用率 / 商店兑换量 | 提热度次数、kflowstore 兑换次数 |
| 留存 | 7 日回访率 | 首次发帖后 7 天内再次访问 |

## 2. Vibecoding 术语表（对应需求第 5 条）

社区统一话语体系，术语页（`/glossary`）按此内容上线，卡片式展示、支持首字母/分类筛选。

| 术语 | 英文 | 一句话解释 |
| --- | --- | --- |
| 氛围编程 | Vibe Coding | 由 Andrej Karpathy 提出的开发方式：用自然语言向 AI 描述需求，由 AI 生成代码，人负责引导、验收和迭代，"沉浸在氛围里，忘记代码本身"。 |
| 提示词 | Prompt | 喂给 AI 的指令文本，写得好坏直接决定产出质量。 |
| 上下文 | Context | AI 当前"能看到"的全部信息（对话、文件、规则），上下文组织得好坏决定输出上限。 |
| 上下文窗口 | Context Window | AI 一次能处理的最大 token 量，超出的内容会"失忆"。 |
| Token | Token | AI 处理文本的最小单位，也是计费单位，约等于 0.5~1.5 个汉字。 |
| 智能体 | Agent | 能自主拆解任务、调用工具、多轮执行直到目标完成的 AI 程序。 |
| 工具调用 | Tool Use / Function Calling | AI 在对话中调用搜索、读写文件、执行命令等外部能力。 |
| MCP | Model Context Protocol | Anthropic 推出的开放协议，让 AI 工具以统一方式接入外部数据源和服务。 |
| 规则文件 | Rules / CLAUDE.md | 放在项目里告诉 AI"这个项目怎么干"的说明书（如 CLAUDE.md、.cursorrules）。 |
| 上下文工程 | Context Engineering | 系统性地准备、裁剪、组织喂给 AI 的信息，是比写单条 prompt 更进阶的功夫。 |
| 一句话应用 | One-shot App | 一条 prompt 直接生成的完整小应用，是 vibecoding 最经典的玩法。 |
| 迭代循环 | Iterative Loop | 描述需求 → 看产出 → 提修改 → 再验收的循环，vibecoding 的基本工作节奏。 |
| 验收标准 | Acceptance Criteria | 提前写清楚"做到什么程度算完成"，防止 AI 自由发挥跑偏。 |
| AI 幻觉 | Hallucination | AI 一本正经地编造不存在的 API、库或事实，需要人工验收兜底。 |
| 人工审查 | Human Review | 人对 AI 产出的检查与修正；vibecoding 不等于不看不测，上线前必须审查。 |
| AI 编程工具 | AI Coding Tools | Cursor、Claude Code、Windsurf、Copilot 等以 AI 为核心的开发环境。 |
| 需求拆解 | PRD / Task Breakdown | 把大想法拆成 AI 能逐步执行的小任务清单，复杂项目必备。 |
| 测试驱动 | Test-Driven Vibe | 先让 AI 写测试再实现功能，用测试自动验收，是"放心 vibe"的保险绳。 |
| 部署 | Deployment | 把做好的应用发布到公网（Vercel、Cloudflare、自有服务器等），社区发帖要求附上线地址。 |

> 上线时由运营补充案例截图与示例 prompt，每条术语可配一个"新手可复制"的小例子。

## 4. 功能需求

> 编号规则：FR-x.y。标注【复用】= 现有能力直接用；【扩展】= 改造现有模块；【新建】= 全新开发。

### FR-1 Vibecoding 排行榜

#### FR-1.1 全网排行榜【新建】

**目标**：聚合站外 vibecoding 项目的热度，形成"全网都在 vibe 什么"的参考榜单。

**数据源方案对比**（已确认接入三类源，具体源上线前按合规评估定稿）：

| 来源 | 获取方式 | 可获得字段 | "热度"口径 | 风险与成本 |
| --- | --- | --- | --- | --- |
| GitHub Trending | 首选：GitHub Search API（官方、免费、带 token 5000 次/h）；兜底：解析 trending 页面 | 仓库名/作者/描述/链接/语言/**Star 数、今日新增 Star** | 平台无浏览量 → 用 **Star 总数 + Star 增速** | 官方 API 合规、稳定；爬页面仅作兜底 |
| Product Hunt | 首选：官方 GraphQL API（需申请 Developer Token）；兜底：RSS/首页解析 | 产品名/Tagline/链接/**Upvote 数**/评论数/发布日 | **Upvote 数** | API 需申请；爬页面有反爬风险 |
| 中文技术社区 | V2EX 有公开 API（hot topics）；掘金/少数派优先走 RSS + 文章页阅读量字段 | 标题/摘要/链接/**阅读量**/评论数 | **阅读量**（视平台可得性，拿不到则用评论/收藏数） | 反爬较严、字段不齐；每家需单独适配，先接 1~2 家跑通 |

**关键规则**：

1. **归一化合成**：三类源热度口径不同（Star / Upvote / 阅读量），各源内先做 log 归一化（`log(1+x)`）再按源权重合成"全网热度分"，避免某一源数值大就霸榜。源权重后台可调。
2. **创意度（需求标注"待定"，给三个候选，上线前定稿）**：
   - 方案 A（推荐先做）：**站内用户投票**——榜单卡片可点赞，点赞数即创意度参考；实现成本最低，与现有点赞体系一致，且能冷启动。
   - 方案 B（二期）：**LLM 评分**——用 LLM 按新颖性/完成度/实用性对项目描述打分（1~10），评分理由落库可解释；有 API 成本，适合日榜精选。
   - 方案 C（辅助）：**客观加权**——是否原创（非 fork）、技术栈稀缺度、描述文本去重相似度等信号加权；可自动化但粗糙。
   - **建议：M2 上线 A，B/C 作为二期迭代**。
3. **榜单内容**：项目卡 = 来源标识 + 标题 + 一句话描述 + 链接（跳转原出处，标注来源）+ 热度值 + 创意度（定稿后）。榜单分 **日榜 / 周榜 / 总榜**。
4. **抓取调度**：每日 1 次（凌晨低峰），实现为 Django management command + 系统 cron；每次抓取记录一条运行日志（来源、开始/结束、条数、错误）。
5. **失败降级**：某源抓取失败时保留上次成功数据继续展示，页面标注"数据更新于 xx 时间"；连续失败 3 次管理后台告警。
6. **去重**：同一项目多源出现时按 URL 归一（GitHub 仓库地址大小写不敏感等）合并，保留多来源热度数据。
7. **合规红线**（详见 §6.1）：只采集公开元数据（标题/链接/计数），不抓正文全文、不绕过登录验证、遵守 robots.txt、官方 API 优先、控制请求频率。

#### FR-1.2 站内排行榜【新建，数据来自现有模块】

**热度公式**（后台可调，存 `SystemSetting`）：

```
热度分 hot_score = (点赞数 × 3 + 评论数 × 5 + 去重浏览数 × 0.2) × 时间衰减
时间衰减 = 1 / (发帖小时数 + 2) ^ 1.2     （Hacker News 风格，越新越占优）
加热加成：生效中的加热包按档位追加固定热度分（见 FR-4.2）
```

1. **作品榜**：按热度分排序，分 **日榜 / 周榜 / 总榜**；每小时由定时任务重算并落库，页面请求只读结果表，不给 SQLite 增压。
2. **创作者榜**：直接基于现有 `PointAccount.contribution_score`（贡献分）与 `reputation_level`（声望等级）排序，展示 头像/昵称/声望/贡献分/代表作。
3. 榜单入口：首页侧栏 TOP10 + `/rankings` 完整页（含"查看更多"）。

### FR-2 用户系统【复用，不改核心】

1. **登录注册完全沿用现有能力**：账号/邮箱注册 + 邮箱验证码、session 登录（8h）、找回密码路径不变；不做 OAuth、不改表结构。
2. **用户主页升级为社区主页**（扩展现有 `forum-profile`）：
   - **作品集 Tab**：该用户发布的帖子（含被点赞总数、总浏览）。
   - **积分与声望 Tab**：积分余额、声望等级、贡献分、最近积分流水（复用 `/api/points/ledger`）。
   - **兑换记录 Tab**：自己的 kflowstore 兑换历史（仅本人可见）。
3. 未登录浏览不受限，互动动作（点赞/评论/发帖/兑换/加热）触发登录引导弹窗。

### FR-3 论坛 / 作品发布

#### FR-3.1 帖子结构【扩展】

现有帖子（`ForumTopic`）为纯文本，扩展为社区作品帖结构：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 标题 | 是 | ≤ 60 字 |
| 一段话介绍 | 是 | 纯文本 ≤ 500 字，说明"做了什么、怎么 vibe 出来的" |
| 图片 | 否，0~9 张 | 走现有 uploads 通道，Pillow 压缩校验；第一张作封面 |
| 项目链接 | 否，0~3 个 | 类型自动识别：GitHub / Gitee / 上线地址（其余域名归"其他"）；每个链接带可编辑的显示名 |
| 标签 | 否，≤ 5 个 | 沿用现有逗号分隔标签 |
| 分类 | 是 | 改造为 vibecoding 主题分类（见 FR-3.4） |

1. 帖子正文支持 **Markdown 渲染**（介绍文字进阶写法；第一期可先"纯文本 + 换行"，Markdown 作为 M1 内的增强）。
2. 图片懒加载 + 点击放大；链接渲染统一 `rel="nofollow noopener"` 并新窗口打开。
3. 发布成功即计积分（FR-4.1）。

#### FR-3.2 点赞【扩展】

1. 帖子点赞沿用现有 `ForumLike`（一人一帖一赞，可取消）。
2. **新增回复点赞**：回复也可被点赞（一人一回复一赞）。
3. 被点赞产生积分（FR-4.1）；自己给自己点赞不计积分。

#### FR-3.3 评论与分享【复用 + 扩展】

1. 评论沿用现有 `ForumReply`（软删除、后台管理不变）。
2. **链接分享**：帖子详情页提供「复制链接」按钮（复制规范 URL + 成功提示）；帖子详情页补齐 OG meta（标题/封面/描述），使微信、X 等外部分享卡片美观。分享计数仅作展示，不计积分。

#### FR-3.4 分类与浏览量【扩展】

1. 分类从现有通用分类改造为 vibecoding 主题（建议 seed：`晒作品` / `求点评` / `一句话应用` / `工具技巧` / `踩坑记录` / `招募合作`），沿用现有 seed 命令机制。
2. 浏览量口径：按「用户（登录）或设备（匿名 cookie）× 每日 × 每帖」去重后 +1，替换现有简单自增；榜单使用去重后浏览数。

### FR-4 积分与活跃

#### FR-4.1 行为积分规则【扩展，基础设施已存在】

完全复用现有积分账本（`PointLedger` 的 `event_type` / `idempotency_key` / `reference_type+id` 扩展点、`SystemSetting` 后台可调规则、幂等事务约定），仅**新增事件类型与规则数值**：

| 行为 | event_type | 积分 | 贡献分 | 每日计分上限（防刷） |
| --- | --- | --- | --- | --- |
| 发帖 | `topic_created` | +10 | +5 | 前 3 帖计分 |
| 帖子被点赞 | `like_received` | +1 | +1 | 前 50 次 |
| 发评论 | `reply_created` | +2 | +1 | 前 10 条 |
| 评论被点赞 | `reply_like_received` | +1 | 0 | 前 20 次 |
| 每日活跃 | `daily_active`（已有） | +2 | +1 | 1 次 |

防刷规则：幂等键 = `事件 + 对象 + 触发者 + 日期`；点赞取消后对应积分不回退但计入当日上限；同一用户对同一对象重复互动只计一次；所有规则数值后台可调。

#### FR-4.2 提帖子热度（抖+ 式加热）【新建】

**玩法**：作者消耗积分给自己的帖子购买曝光，类似抖音"抖+"。

| 档位 | 价格（积分） | 热度加成 | 生效时间 | 附加权益 |
| --- | --- | --- | --- | --- |
| 🔥 小火 | 100 | +300 | 24h | 进入「加热推荐」流加权 |
| 🔥🔥 中火 | 300 | +1000 | 48h | 加权更强 + 帖子卡片 🔥 标 |
| 🔥🔥🔥 大火 | 1000 | +3600 | 72h | 上述全部 + 首页推荐位轮播 |

规则：

1. 仅**作者本人**可加热自己的帖子，帖子状态须为 open。
2. 同一帖子**同时最多 3 个生效加热包**，可叠加（时长与热度分累加）。
3. 加热消耗积分即时到账生效，**不可退款**；帖子因违规被删除时，未过期的加热包按剩余时长折算退还积分。
4. 新建 `TopicBoost` 表（帖子/用户/扣分/加成分/起止时间/状态），扣分走 `PointLedger` 幂等流水；每小时榜单重算时纳入生效中的加热加成。
5. 档位价格与加成数值后台可调，上线后按数据调优。

#### FR-4.3 kflowstore 升级【复用官方货架 + 新建创作者货架】

kflowstore（在现有"K 士多"基础上升级，`/store`）分为两个货架：

**A. 官方货架【复用】**：现有 `StoreProduct / StoreCode / StoreRedemption` 的积分兑换码模式原样保留（商品、库存兑换码、幂等兑换事务、管理后台上架均不动）。

**B. 创作者货架【新建】——用户上架自己的东西，他人用积分兑换**：

| 环节 | 规则 |
| --- | --- |
| 谁能上架 | 任意登录用户；同一用户同时最多 10 个在售商品 |
| 卖什么 | 仅限**数字商品**：资源包、prompt 合集、模板/组件、教程、自产兑换码等；禁止实物、现金交易、违规内容（首批类目清单上线前定稿，见开放问题） |
| 交付物 | 上架时绑定交付方式：文本说明 / 兑换码（批量导入）/ 外部链接（网盘/仓库），买家兑换成功后立即可见 |
| 审核 | 提交后进入审核（复用现有 publishing 审批流，先走管理员单人审核，加权投票作为二期）；审核通过才可见、可售 |
| 定价 | 以积分计价（≥ 10 分），价格卖家自定、可改价（改价不影响已成交） |
| 交易 | 复用 `StoreRedemption` 的幂等事务模式：买家扣积分 → 交付物发放 → 卖家入账，一步事务内完成 |
| 结算 | 卖家获得售价 **100%**（M3 先不抽成，抽成比例列开放问题）；入账走 `PointLedger` 新事件 `listing_sold` |
| 库存/限购 | 支持限量库存与每人限购（沿用现有字段语义） |
| 上下架 | 卖家可自主上架/下架；管理员可强制下架并填写理由；下架不影响已完成交易 |
| 纠纷原则 | 交易不可逆（积分已入卖家账）；商品描述与交付物不符由管理员仲裁，可对卖家扣分/冻结（复用积分冻结能力）；平台不担保外部链接内容 |

### FR-5 术语页【新建】

1. 页面 `/glossary`：卡片式术语展示，按分类（基础概念 / 工具 / 工作流）分组，支持关键词过滤；内容即 §2 术语表。
2. 首页侧栏随机展示 3 条术语卡，点击进术语页。
3. 术语数据建 `GlossaryTerm` 表，管理后台可增改（运营维护），无需发版。

### FR-6 教程页【新建】

1. **内容范围**：
   - **简单教程**（手把手系列）：如「10 分钟做出第一个网页小游戏」「用一句话应用开始」「把作品部署上线并来发帖」；
   - **vibecoding 范式介绍**：几种典型工作流——一句话起步 / 计划先行（PRD 拆解）/ 测试驱动 / 迭代打磨，每篇讲适用场景 + 完整示例 prompt。
2. **结构**：教程 = 封面 + 标题 + 摘要 + 正文（Markdown）+ 难度（入门/进阶）+ 标签 + 阅读时长；支持系列（同一系列按顺序展示）。
3. **管理**：新建 `Tutorial` 表，管理后台新增「教程」Tab（Markdown 编辑、预览、发布/下架），无需发版更新内容。
4. 教程底部固定引导：「用这篇教程做了东西？[来发帖晒作品]()」。

## 6. 非功能需求

### 6.1 安全与合规

1. **爬虫合规**：仅采集公开元数据（标题/链接/公开计数），不抓正文全文、不转载内容；遵守目标站 robots.txt；请求频率 ≥ 5 秒/次/源，UA 标识 `KFlowBot/0.1 (+站点地址)`；遇 403/429 立即指数退避并暂停该源；官方 API 优先于页面解析。
2. **外链安全**：帖子与商店外链统一 `nofollow noopener`；商品外部交付链接管理员审核时抽检。
3. **内容安全**：图片上传沿用 Pillow 校验 + 压缩；商店商品与交付物必须经审核；保留现有软删除与管理员下架能力。
4. **防刷**：积分幂等 + 每日上限（FR-4.1）；加热只能本人操作；榜单重算在服务端，不信任前端计数。

### 6.2 性能与部署

1. SQLite（WAL）单写者：榜单/全网榜一律**预计算落库**，页面只读；发帖图片压缩后落 `uploads/`；列表接口分页沿用现有约定。
2. 定时任务（榜单重算每小时、全网抓取每日）用 management command + 系统 cron，与现有 imaging worker 部署方式并列，写进 `redeploy-with-tunnel.sh` 注释文档。
3. 备份沿用 `scripts/backup_sqlite.py`，新表随 Django migration 正常迁移（上线前先手动备份一次，符合现有脚本约定）。
