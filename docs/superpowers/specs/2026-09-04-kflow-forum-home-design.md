# KFlow 社区首页设计

日期：2026-09-04  
状态：已获用户批准

## 1. 目标

在 KFlow 中新增一个位于 `/forum` 的社区首页原型。页面借鉴 LinuxDo 一类现代论坛的高密度信息组织方式，但不复制其品牌、图标、文案或具体视觉资产。首期只实现可浏览、可筛选的首页，不建立帖子、回复等数据库模型。

该页面服务于 KFlow 产品与技术社区，帮助用户发现产品动态、交流技术问题、获取使用帮助、分享资源并展示项目。

## 2. 范围

### 本期包含

- 新增独立静态论坛页面 `/forum`。
- KFlow 首页顶部导航增加“社区”入口。
- 展示论坛分类、主题列表、公告、热门话题、活跃贡献者和社区数据。
- 支持浏览器端关键词搜索。
- 支持按分类筛选主题。
- 支持“最新”“热门”“精华”三种视图或排序方式。
- 支持桌面、平板和手机响应式布局。
- 对尚未实现的发帖、帖子详情、回复、收藏和点赞操作给出明确的“即将开放”提示。

### 本期不包含

- 不新增论坛数据库表。
- 不实现真实发帖、回复、点赞、收藏、关注或通知。
- 不新增管理员论坛审核功能。
- 不修改现有账户、积分、产品、下载或发布 API。
- 不复制 LinuxDo 的商标、专有文案、图标或页面像素级样式。

## 3. 技术方案

采用独立静态页面方案，与项目现有静态前端保持一致：

- `static/forum.html`：语义化页面结构和无脚本回退内容。
- `static/forum.css`：论坛专属视觉和响应式样式。
- `static/forum.js`：示例主题数据、搜索、筛选、排序和原型提示。
- `apps/core/pages.py`：在 `PAGE_MAP` 中注册 `forum.html`。
- `apps/core/urls.py`：注册 `/forum` 页面路由。
- `static/index.html`：顶部导航增加“社区”链接。

论坛数据只存在于前端 JavaScript 中。页面加载后，状态由搜索词、当前分类和当前视图共同决定，随后过滤、排序并渲染主题列表。

## 4. 信息架构

### 4.1 顶部导航

顶部栏包含：

- KFlow Community 品牌标识。
- “话题”“分类”“精华”快捷入口。
- 桌面端搜索框或搜索入口。
- “返回 KFlow”链接。
- 登录或账户入口。

顶部栏在页面滚动时保持可见，使高密度主题列表仍易于导航。

### 4.2 左侧分类栏

分类固定为：

1. 全部话题
2. 产品动态
3. 技术交流
4. 使用帮助
5. 资源分享
6. 项目展示
7. 闲聊广场

桌面端使用纵向分类列表；手机端转换为可横向滚动的分类标签，不占用主题流宽度。

### 4.3 中央主题流

中央区域是页面主内容，包含：

- 社区欢迎或状态提示。
- “最新”“热门”“精华”切换控件。
- 关键词搜索。
- 主题条目列表。

每个主题条目展示：

- 作者头像与作者名。
- 主题标题和短摘要。
- 所属分类。
- 置顶或精华状态。
- 最后活跃时间。
- 回复数和浏览数。

置顶主题优先呈现。点击主题时不跳转到不存在的详情页，而是显示“帖子详情功能即将开放”的非阻塞提示。

### 4.4 右侧信息栏

右侧栏包含：

- 社区公告。
- 热门话题排行。
- 活跃贡献者头像与名称。
- 主题数、成员数、今日互动等示例统计。

这些内容用于建立完整论坛首页的视觉层次，本期均为明确的示例数据。

## 5. 视觉设计

采用用户选定的“A · KFlow 清爽社区”方向：

- 页面主背景使用冷调浅灰，内容区域使用白色。
- KFlow 红色作为主强调色，用于当前分类、关键状态和交互反馈。
- 辅助颜色按不同分类区分，但保持低饱和度。
- 使用细分割线、轻量阴影、紧凑圆角和圆形头像。
- 保持论坛应有的信息密度，同时通过标题、元信息和数字列建立清晰层级。
- 动画仅用于页面进入、筛选更新和提示出现，遵守 `prefers-reduced-motion`。
- 字体采用适合中文长时间阅读的本地字体栈，避免依赖外部字体服务。

## 6. 交互规则

### 搜索

搜索框匹配主题标题、摘要、作者、分类和标签。输入时即时刷新结果，并显示匹配数量。没有结果时提供清晰的空状态和重置入口。

### 分类筛选

选择分类后只显示对应主题。当前分类在桌面侧栏和手机分类条中均有明确选中状态。

### 视图切换

- 最新：按最后活跃时间排序。
- 热门：按热度分值排序，热度由示例数据直接提供，避免运行时产生不稳定结果。
- 精华：仅显示标记为精华的主题，并按活跃时间排序。

### 未开放功能

“发起新话题”、主题条目和回复、收藏、点赞入口统一触发页面内 Toast 提示。提示可自动消失，也可由用户关闭；不使用阻塞式浏览器 `alert`。

## 7. 响应式与可访问性

- 大屏：左侧分类、中间主题流、右侧信息栏三栏布局。
- 中屏：隐藏右侧信息栏，保留分类与主题流。
- 小屏：单列主题流，分类改为横向滚动标签，主题统计压缩但不丢失关键信息。
- 所有可交互元素使用原生按钮或链接，支持键盘焦点。
- 搜索框包含可见标签或辅助文本。
- 当前筛选状态通过 `aria-pressed` 或等价语义表达。
- 颜色对比度以浅色背景下正文可读性为优先。
- 空状态和 Toast 使用适当的状态语义。

## 8. 路由与兼容性

- `/forum` 通过 Django 静态页面视图提供，并设置 CSRF cookie，与其他公开页面行为一致。
- `/forum` 无需登录即可访问。
- 首页“社区”导航使用绝对路径 `/forum`。
- 现有静态资产路由继续用于加载 `/forum.css` 和 `/forum.js`。
- 不改变现有 URL、Cookie 名称或 API 响应结构。

## 9. 错误与降级处理

- JavaScript 未加载时，HTML 中仍保留基本页面说明和若干示例主题，使页面不是空白。
- 搜索无结果时展示空状态，不抛出异常。
- 缺失头像使用 CSS 生成的文字头像，不依赖远程图片。
- JavaScript 初始化时检查目标元素是否存在，避免单个组件缺失导致整页失效。

## 10. 验证方案

### Django 验证

- `/forum` 返回 HTTP 200。
- 响应包含论坛页面的关键品牌文本。
- `manage.py check` 通过。
- `makemigrations --check --dry-run` 不产生迁移。

### 前端验证

- 分类筛选只显示匹配主题。
- 关键词搜索可匹配标题、作者和标签。
- 最新、热门和精华视图结果正确。
- 清除搜索和筛选后恢复完整主题列表。
- 发帖和帖子详情显示“即将开放”提示。
- 浏览器控制台无 JavaScript 错误。

### 视觉验证

使用桌面与移动视口检查：

- 三栏、两栏和单栏断点正确。
- 顶部导航、分类条和主题列表无横向溢出。
- 文本不会遮挡回复数和浏览数。
- 键盘焦点清晰可见。

## 11. 完成标准

当 `/forum` 可公开访问、首页导航可进入社区、示例主题可以搜索/分类/排序、未开放功能有一致提示、响应式布局正常且 Django 检查通过时，本期论坛首页原型完成。
