# KFlow 后台二级路由与按需加载设计

## 背景与目标

后台此前把产品、审批、积分、商城、股市、显影配置和用户管理全部堆在一个 `admin.html` 页面，通过锚点跳转。页面过长，首次打开还会并发请求全部后台接口，导致定位成本和首屏请求量都偏高。

本次改造将后台切成可直接访问的二级路由，同时继续复用现有静态页面和 DOM 事件，不引入前端框架或新的业务 API。

## 路由结构

| 路由 | 工作区 | 初始化数据 |
| --- | --- | --- |
| `/admin` | 运营总览 | 收件箱 |
| `/admin/products` | 产品管理与编辑 | 产品 |
| `/admin/reviews` | 下载审批、发布审核、版本历史 | 产品下拉、下载审批、发布审核 |
| `/admin/points` | K 积分管理 | 积分设置与账户 |
| `/admin/store` | K 士多 | 商品与兑换记录 |
| `/admin/market` | K 股市 | 轮次、资产、库存、订单、资金与审计 |
| `/admin/imaging` | 显影配置 | 显影服务配置 |
| `/admin/users` | 用户管理 | 用户列表 |
| `/admin/settings` | 上传限制与管理员激活码 | 激活码；上传限制沿用认证响应 |
| `/admin/bigscreen` | 数据大屏 | 复用既有独立页面 |

所有后台二级页面由 Django 进行管理员认证，未登录时将当前路径写入 `next`，登录成功后回到原页面。

## 前端行为

- `admin.html` 根据当前 `window.location.pathname` 只显示对应工作区的 section。
- 侧栏使用真实路径而非页面内锚点，当前路由有独立激活态，可复制 URL 直达。
- 顶部“产品编辑”在其他工作区跳转到 `/admin/products#productEditorSection`，在产品页内执行平滑定位。
- 审批页加载轻量产品列表下拉，用于选择版本历史，不把完整产品编辑器重复带入审批工作区。
- 收件箱作为顶部跨工作区能力保留一次轻量请求，其余 API 仅由当前路由加载。

## 权限与失败处理

- 产品、审批和用户路由沿用现有管理员权限；积分、士多、股市、显影仍限制主管理员。
- 系统设置允许主管理员或 lv3 访问；激活码仍只有主管理员可操作，上传限制仍只有 lv3 可修改。
- 直接访问无权限路由时不加载业务 API，页面显示权限提示。
- API 返回 401 时回到登录页并保留当前路由，不丢失用户上下文。

## 验证

- Django 路由测试覆盖所有二级页面的未登录重定向和登录后页面渲染。
- `manage.py check`、全量 Django 测试和 `admin.html` 内联 JavaScript 语法检查必须通过。
