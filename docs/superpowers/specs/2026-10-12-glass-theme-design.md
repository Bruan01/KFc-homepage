# KFlow 前台玻璃透明主题设计

日期：2026-10-12  
状态：已获用户批准

## 1. 目标

为 KFlow 前台增加第三种 UI 风格“玻璃透明”，视觉参考哲风壁纸社区的深色半透明面板、胶囊导航、细边框高光和背景模糊层次。主题可与现有“白天 / 黑夜”模式并列切换。

本期只调整前端主题样式和主题状态，不改变现有页面分布、DOM 信息架构、后端接口、数据库、业务流程或 URL。

## 2. 范围

### 本期包含

- 前台主题状态扩展为 `light`、`dark`、`glass` 三种模式。
- 现有主题按钮循环切换 `light → dark → glass → light`，并保留本地存储。
- 新增独立玻璃主题覆盖样式，统一覆盖前台导航、卡片、面板、表单、按钮、标签、弹窗、列表和页脚。
- 前台页面加载玻璃主题样式和主题脚本，使跨页面跳转后保持所选主题。
- 使用 CSS 变量组织玻璃主题色彩、边框、阴影、模糊和交互状态。
- 对不支持 `backdrop-filter` 的浏览器提供不透明半透明色回退。
- 继续遵守 `prefers-reduced-motion`，降低或关闭主题过渡动画。

### 本期不包含

- 不修改后台 `admin.html`、`admin-login.html`、`admin-register.html`、`admin-bigscreen.html` 的主题或布局。
- 不修改 Django views、models、迁移、API、数据库和用户权限。
- 不新增页面，不移动现有组件，不改变响应式断点和栅格分布。
- 不引入构建工具、第三方字体、第三方 CSS 框架或远程图片资源。
- 不复制参考站点的品牌、文案、图标或具体页面布局。

## 3. 技术方案

采用“独立覆盖样式 + 三态主题状态”的方案：

- `static/theme.js`：扩展合法主题值、主题应用逻辑、主题按钮标签和图标状态，并保持 `kflow-theme` 存储键兼容。
- `static/glass-theme.css`：新增只在 `:root[data-theme="glass"]` 下生效的全局玻璃主题覆盖层，放在页面专属 CSS 之后加载。
- `static/*.html`：除后台页面外，补充主题脚本与玻璃样式入口；不调整页面内容顺序和容器层级。
- 现有 `styles.css`、`forum.css`、`community.css`、`learn.css`、`rankings.css`、`gamification.css`、`store.css` 保持原有 light/dark 规则，不将玻璃规则分散复制到各页面样式中。

主题脚本在 head 中尽早运行，先读取 `localStorage`，再设置 `data-theme`，降低刷新时的主题闪烁。没有保存主题时继续遵循系统 `prefers-color-scheme`，默认选择 light 或 dark；glass 只由用户主动选择。

## 4. 主题状态与交互

### 4.1 状态

| 主题 | 根节点状态 | 说明 |
| --- | --- | --- |
| 白天 | 无 `data-theme` 或 `data-theme="light"` | 沿用当前浅色主题 |
| 黑夜 | `data-theme="dark"` | 沿用当前深色主题 |
| 玻璃 | `data-theme="glass"` | 启用 Midnight Frost 玻璃视觉 |

旧版本 localStorage 中的 `light`、`dark` 值继续有效；未知值按系统偏好回退。

### 4.2 切换按钮

- 点击一次按 `light → dark → glass → light` 循环。
- `aria-pressed` 在三态之间保持语义明确；`title` 和可见文本同步显示下一步可切换到的主题或当前主题名称。
- 玻璃模式使用折射/叠层风格的内联 SVG 图标，不新增图片资源。
- 主题切换过渡只影响视觉，不阻塞导航、表单提交或异步请求。

## 5. 视觉设计

主题名称为“Midnight Frost”，采用有辨识度的深色玻璃而不是普通暗色模式：

- 页面底色：深墨蓝黑渐变，叠加青绿、冰蓝和少量紫红的低饱和径向光晕。
- 主表面：`rgba(255,255,255,.08)` 左右的半透明白色，配合 `backdrop-filter: blur(22px) saturate(135%)`。
- 面板边缘：1px 半透明白边，顶部或左上侧增加极细高光，避免组件融入背景。
- 阴影：使用宽、低透明度的深色阴影与少量彩色环境光，保持层次但不改变布局尺寸。
- 强调色：冰青色用于链接、当前态和成功反馈；暖珊瑚色只用于重要操作或警示。
- 文字：主文字接近冰白，次级文字使用低透明度冷灰；所有正文和表单占位符维持可读对比度。
- 圆角：复用现有组件尺寸，只调整背景、边框和阴影，不通过改变 padding 或 width 造成重排。

## 6. 组件覆盖策略

玻璃主题按照现有选择器进行样式覆盖：

- `body`、页面背景伪元素：建立固定氛围背景和轻微噪点/光晕，不遮挡内容。
- `.forum-header`、`.topbar`、导航、搜索框：使用高透玻璃和底部细边框；下拉菜单提高不透明度确保文字可读。
- `.card`、`.panel`、`.topic-list-card`、`.community-sidebar`、`.side-card`、`.hero`：统一玻璃表面、边缘高光和悬停浮起效果。
- `.btn`、`.community-cta`、`.view-tab`、`.subtab`、`.theme-toggle-btn`：用透明填充、边框和强调色区分默认、悬停、激活和禁用态。
- `input`、`textarea`、`select`、`.markdown-preview`：使用深色半透明控件背景、内边框和聚焦光环。
- 表格、排行、学习卡片、商店卡片、统计模块：只改变表面与色彩，不改变原有行列关系。
- 弹窗、通知、Toast、用户菜单和导航下拉：使用更高不透明度和更强边框，确保浮层与背景分离。
- 图片和媒体：保留原始尺寸与裁剪规则，只增加圆角、边框和悬停高光。

## 7. 多页面与后台边界

主题资源加载范围是前台静态页面，不包括四个后台页面。`user-login.html` 视为前台入口，使用玻璃主题；后台页面继续使用原有 `styles.css` 和 light/dark 逻辑。

玻璃主题样式必须以 `data-theme="glass"` 为作用域，不得覆盖未选择玻璃主题时的现有 CSS。页面即使暂时缺少主题切换按钮，只要加载 `theme.js`，也应正确读取已保存的主题并保持视觉一致。

## 8. 响应式与可访问性

- 保持当前媒体查询、容器宽度、列数和移动端折叠方式不变。
- 玻璃层在小屏设备上降低 blur 和阴影强度，减少 GPU 压力。
- 通过 `@supports` 提供 `backdrop-filter` 不可用时的实色半透明回退。
- 交互元素保留现有键盘焦点样式；玻璃主题下焦点环使用高对比冰青色。
- `prefers-reduced-motion: reduce` 下关闭背景光晕动画、浮起动画和主题淡入过渡。
- 不依赖颜色单独表达状态，激活态同时保留边框、文字或图标变化。

## 9. 错误与降级处理

- localStorage 不可用时，主题仍可在当前页面切换，但不持久化。
- 读取到未知主题值时回退到系统偏好，不阻塞页面渲染。
- CSS 特性不支持时使用不透明背景、普通边框和阴影，保证内容与交互可用。
- 单个页面缺少某个组件选择器时，玻璃主题只跳过该组件，不影响其他页面。

## 10. 验证方案

### 静态验证

- `theme.js` 只接受 `light`、`dark`、`glass`。
- 后台 HTML 不引用 `glass-theme.css`，不加载新增玻璃状态入口。
- 所有前台 HTML 都能加载主题脚本和玻璃覆盖样式。
- `data-theme="glass"` 选择器不存在未作用域化的全局覆盖。

### 浏览器验证

- 白天、黑夜、玻璃三态循环正确，刷新后主题保持。
- 在首页、社区、商店、产品、学习、排行、账户和登录等前台页面切换后，视觉状态一致。
- 导航下拉、搜索、表单、弹窗、Toast、用户菜单和按钮在玻璃模式下仍可操作。
- 窄屏下无横向溢出，现有布局分布与断点不变。
- 浏览器控制台无新增 JavaScript 错误。

### Django 验证

- `manage.py check` 通过。
- `makemigrations --check --dry-run` 不产生迁移。
- 现有 Django 测试通过。

## 11. 完成标准

当前台页面可以通过现有主题入口切换白天、黑夜和玻璃三种风格，玻璃模式在各前台页面保持统一的半透明视觉，后台页面保持原样，现有布局/API/业务功能未发生变化，并通过静态、浏览器和 Django 验证时，本期完成。
