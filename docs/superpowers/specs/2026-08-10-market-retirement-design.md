# K 股市完整退役设计

- 日期：2026-08-10
- 状态：用户已选择方案 A，待审阅本文档后进入实施计划
- 范围：用户端、后台端、市场 API、Django 应用、数据库表与历史市场数据

## 1. 目标

从 KFlow 中完整移除 K 股市功能，不保留可访问入口、业务 API、市场运行代码或历史市场数据，同时不影响产品、下载、积分、K 士多、显影及账户功能。

## 2. 采用方案

采用完整删除方案：

1. 删除用户端 `/market` 页面和所有市场导航入口；
2. 删除后台 `/admin/market` 页面、导航入口、市场管理模块和前端请求逻辑；
3. 删除 `apps/market` 的 URL、视图、服务、模型、测试、应用配置和历史迁移源文件；
4. 从 `INSTALLED_APPS` 和根 URL 配置中移除 market 应用；
5. 新增独立的市场退役迁移，删除所有 market 数据表及其历史数据；
6. 清理 README、TODO 与设计文档中将 K 股市描述为现有能力的内容；
7. 旧市场页面和 API 不设兼容代理，统一返回 404。

## 3. 数据库退役

市场应用当前的数据包括轮次、资产、机器人库存、用户持仓、交易订单、用户每日用量、机器人每日用量和管理员审计等表。

新增一个不再依赖 market 应用运行时模型的迁移，按依赖安全的反向顺序删除表及数据：

1. 审计、日用量、订单、持仓与机器人库存；
2. 资产与轮次；
3. 对应索引、约束和 market 应用迁移状态。

迁移执行后，现存市场历史数据永久删除。积分账本保留，因为它属于通用积分域；其中已有的市场关联历史账本仍然作为财务审计记录存在，但不再由任何市场接口展示或新增。

## 4. 路由与前端

### 用户端

- 从 `PAGE_MAP` 删除 `/market`；
- 删除主页、账户页、积分页等涉及市场的导航/推广内容；
- 删除 `static/market.html`。

### 管理端

- 从 `PAGE_MAP` 删除 `/admin/market`；
- 从 `static/admin.html` 删除 K 股市侧栏入口、市场区块、DOM 引用、路由配置、加载函数、提交函数及事件监听；
- 后台其余路由与权限规则保持不变。

### 后端

- 从根 URL 配置删除 market URL include；
- 从 Django `INSTALLED_APPS` 删除 market AppConfig；
- 删除市场应用文件；
- 保留 `apps.points` 及其通用账本能力。
