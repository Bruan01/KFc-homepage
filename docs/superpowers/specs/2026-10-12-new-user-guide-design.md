# KFlow 新手指南页面设计

## 1. 目标

新增一个独立的 `/guide` 页面，站在“第一次来到 KFlow 社区的新手”角度，系统说明网站的公开页面、页面用途和下一步行动。

教程的目标不是介绍后台配置，也不是复制现有的 Vibecoding 开发者手册，而是让新用户在一次连续阅读中建立以下认知：

1. KFlow 社区首页和论坛如何使用。
2. 如何注册、登录、完善个人身份并参与讨论。
3. 如何发现热门项目、贡献者和学习内容。
4. 如何使用显影、产品站、积分和商店。
5. 如何理解个人成长、成就、等级和服务状态。

管理员后台、管理员登录注册、`/admin/*` 页面和后台 API 不属于教程范围。

## 2. 用户路径与内容结构

页面采用单页滚动式新手旅程，主线为：

> 认识社区 → 建立身份 → 发现内容 → 学习查词 → 动手创作 → 获取产品 → 积分与商店 → 成长与成就 → 服务与外部入口

| 章节 | 覆盖入口 | 新手需要理解的内容 |
| --- | --- | --- |
| 1. 先认识社区 | `/`、`/forum`、主题详情、分享主题 | 首页信息、论坛分类、主题阅读和讨论入口 |
| 2. 建立身份 | `/login`、`/account`、`/forum/user/<username>` | 注册登录、资料设置、个人主页与个人中心区别 |
| 3. 发现热门内容 | `/rankings`、排行榜项目详情、`/stats` | 项目热度、站内内容、贡献者和社区统计 |
| 4. 学习与查词 | `/tutorials`、教程详情、`/glossary`、词条详情 | 教程与术语表的用途和使用方式 |
| 5. 动手创作 | `/imaging` | 显影、模板、生成、历史记录和下载 |
| 6. 获取产品 | `/products`、产品详情 | 产品浏览、版本信息、下载和安装信息 |
| 7. 积分与商店 | `/points`、`/store` | K 积分来源、兑换、创作者货架和消费路径 |
| 8. 成长与成就 | `/achievements`、`/levels` | 勋章、等级、贡献值和个人展示 |
| 9. 服务与外部入口 | `/service-status`、`/newapi`、`/cardloom` | 服务状态、API 中转站别名和独立产品入口 |

`/newapi` 与 `/service-status` 展示同一类服务状态内容，在教程中合并说明一次。论坛主题详情、分享主题、排行榜项目详情和产品详情作为对应章节的深入入口，不单独占用一级章节。

每一章使用统一的三段式说明：

- **你会看到什么**：用新手语言解释页面的定位和主要区域。
- **现在建议做什么**：给出一个可立即执行的小动作。
- **进入真实页面**：提供指向对应页面的按钮或链接。

## 3. 页面布局与视觉方向

页面采用“新手入站地图”方向，保持社区现有导航和色彩基础，同时区别于 `/tutorials` 的电子书阅读器。

### 3.1 页面框架

- 沿用 `forum-header` 和现有社区导航，在导航的“发现”分组加入“新手指南”。
- 首屏标题为“第一次来到 KFlow？从这里开始”。
- 首屏右侧使用带节点的路线图，表达“认识、加入、探索、创作、成长”五个阶段。
- 主体为桌面端双栏布局：左侧固定目录与进度，右侧章节内容。
- 移动端将目录转换为顶部横向滚动导航，章节内容改为单栏。

### 3.2 章节组件

每章包含：

- 章节编号和阶段标签。
- 页面用途说明。
- “建议动作”提示块。
- 一个或多个页面入口卡片，包含页面名称、路径、简短说明和直达按钮。
- 完成当前章节按钮。

页面示意使用 CSS 结构化卡片和现有图标，不新增外部图片或第三方组件。

### 3.3 交互行为

- `IntersectionObserver` 根据当前可见章节高亮左侧目录。
- 点击目录平滑滚动到对应章节。
- 完成状态和当前章节写入 `localStorage`，无需登录和后端同步。
- 顶部和侧栏显示完成数量，例如 `4 / 9 已完成`。
- 真实入口默认在新窗口打开，保证新手返回时不会丢失教程位置。
- 遵循键盘焦点、语义化标题和 `prefers-reduced-motion` 设置。

## 4. 技术实现

新增文件：

- `static/guide.html`：页面结构和教程文案。
- `static/guide.css`：页面专属布局、视觉和响应式样式。
- `static/guide.js`：目录、滚动、进度和本地完成状态。

路由接入：

- 在 `apps/core/pages.py` 的 `PAGE_MAP` 增加 `"guide": "guide.html"`。
- 在 `apps/core/urls.py` 增加 `/guide` 页面路由。
- 在现有公开社区页面的“发现”导航中加入 `/guide` 入口。

本次不新增：

- API 接口。
- 数据库模型或迁移。
- 管理员后台配置。
- 教程后台编辑能力。
- 第三方 JavaScript 或 CSS 依赖。

## 5. 验收标准

### 内容

- `/guide` 覆盖设计表中的全部公开页面类别。
- 页面明确排除管理员后台和后台接口。
- 每个章节都有页面用途、建议动作和真实入口。
- 语言从新手视角出发，不假设用户已经理解 KFlow 的术语。

### 功能

- `/guide` 可通过 Django 路由访问并返回页面。
- 桌面端目录会随滚动更新当前章节。
- 章节完成状态刷新页面后仍保留。
- 移动端目录和章节内容不发生横向溢出。
- 页面入口链接均指向当前仓库已有的公开路由。

### 工程与可访问性

- `python manage.py check` 通过。
- 现有测试不受影响。
- 页面具备清晰的标题层级、可见键盘焦点和减少动画支持。
- 不修改管理员页面和管理员导航。
