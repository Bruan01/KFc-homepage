# 墨水屏上手 · 零基础实操手册

> 给完全没碰过硬件的软件工程师。每一关只有一个验收标准，过了才走下一关。
> 配套技术方案书：`docs/epaper-kbadge-spec.md`

---

## 先建立心智模型

你写 Django 时，程序跑在操作系统上，有日志、有断点、有 F5。

单片机没有这些。它是一台**没有操作系统的电脑**：程序编译成一个二进制文件，烧进 Flash，上电就从第一行开始跑，跑到死循环为止。没有进程，没有文件系统（Flash 可以当磁盘用，但要自己实现），没有 stdout——除非你显式打开串口往外打字。

所以硬件调试的本质是：**你看不见状态，只能设计一个"看得见的结果"来验证一件事。**

这就是为什么下面每一关只验证一个东西。

| 软件里的概念 | 硬件里的对应物 |
|---|---|
| 变量 | 寄存器（就是内存里的一个地址） |
| `pinMode(4, OUTPUT)` | 把某个寄存器的某个 bit 设成"输出方向" |
| `digitalWrite(4, HIGH)` | 把那位置 1，物理上那个引脚变成 3.3V |
| `Serial.print()` | 往串口发字节，电脑上开"串口监视器"看 |
| 部署上线 | 烧录（把二进制写进 Flash，重启生效） |
| `localhost:8000` | 引脚号和波特率 |
| 依赖版本冲突 | 电压不匹配，后果是冒烟 |

逻辑电平只有两个：**3.3V = 1，0V = 0**。所有数字电路都在这个约定下工作。

**为什么必须共地（GND 对 GND）**：电压是"两点之间的差"。两块板子如果不共享同一个 0V 参考点，你说的 3.3V 在对方眼里可能是 0V，也可能是 6V。这是新手第一大坑，占故障的一半。

## 第 0 关：环境能烧录

**验收标准：板载 LED 开始闪。**

零件没到也能做——这关只用开发板和 USB 线，而且下载最耗时，建议先做。

### 0.1 装 Arduino IDE

1. 去 `arduino.cc/en/software` 下载 **Arduino IDE 2.x**（macOS Apple Silicon 版）
2. 打开后进 **设置**（macOS 是 `Arduino IDE → Settings`）
3. 找到「Additional boards manager URLs」，填入：
   ```
   https://espressif.github.io/arduino-esp32/package_esp32_index.json
   ```
4. 左侧点 **Boards Manager**（开发板管理器），搜索 `esp32`
5. 装 **esp32 by Espressif Systems**。这个包约 1–2 GB，国内下载可能要半小时以上，**先在后台挂着**。

> 如果开发板管理器里直接能搜到 esp32，说明你的版本已内置索引，跳过第 3 步。

### 0.2 插上板子，看电脑认不认

用 USB-C 线连上电脑，然后在终端执行：

```bash
ls /dev/cu.*
```

三种结果：

| 看到什么 | 含义 | 怎么办 |
|---|---|---|
| `cu.usbmodem****` | 原生 USB，系统自带驱动 | 直接用 |
| `cu.wchusbserial****` | CH343/CH340 串口芯片 | 能连就说明驱动在；连不上装 WCH 驱动 |
| 什么都没多出来 | 线是"充电线"或板子没上电 | 换一根**数据线**再试 |

> 这一步排除的故障比后面所有步骤加起来都多。**先确认线是数据线。**

### 0.3 烧一个 Blink

1. 开发板选 **ESP32C3 Dev Module**（工具 → 开发板）
2. 端口选上一步看到的那个 `/dev/cu.*`
3. 打开 `文件 → 示例 → 01.Basics → Blink`
4. 把里面的 `LED_BUILTIN` 改成 **8**（ESP32-C3 开发板的板载 LED 多数接在 GPIO8）
5. 点上传（→ 按钮）

看到 LED 一闪一闪，第 0 关通过。

**如果上传失败**：按住板子上的 `BOOT` 键不放，点上传，等出现 `Connecting...` 再松开。有些板子需要手动进下载模式。

## 第 1 关：接线，点亮屏幕

**验收标准：屏幕显示白底 + 一行黑字。**

### 1.1 认识手上的东西

- **杜邦线**：一头是针（公），一头是孔（母）。买的是**母对母**，两头都是孔，用来连接两块都有针的板子——直接插，不用焊。
- **丝印**：板子和屏幕模块上印的白色小字，是唯一的说明书。**只信丝印，不信位置顺序。**
- **针脚编号**：模块上的 8 个孔，按丝印挨个对应，从左到右的顺序在不同批次可能不同。

### 1.2 接线（断电操作）

**插线之前一定先拔掉 USB。** 带电插错一次，屏幕就废了。

按方案书第 4 章的引脚表接 8 根线：

| 屏幕模块 | ESP32-C3 |
|---|---|
| VCC | 3V3 |
| GND | GND |
| DIN | GPIO6 |
| CLK | GPIO4 |
| CS | GPIO7 |
| DC | GPIO5 |
| RST | GPIO3 |
| BUSY | GPIO10 |

三条铁律：

1. **VCC 只接 3V3，永远不接 5V**（有的板子有 5V 脚，接上去屏幕报废）
2. **GND 必须接**，不接的话屏幕会乱码或白屏
3. **不要热插拔**，任何接线动作都先断电

### 1.3 跑最小示例

把方案书附录 A 的代码粘进 Arduino IDE。**型号那一行要改**：

```cpp
GxEPD2_3C<GxEPD2_290_Z13c, GxEPD2_290_Z13c::HEIGHT / 2> display(
    GxEPD2_290_Z13c(EPD_CS, EPD_DC, EPD_RST, EPD_BUSY));
```

`GxEPD2_290_Z13c` 是猜测值。找到真实型号的两个办法：

1. **翻背面**：屏幕背面贴纸或 FPC 排线上印着型号（形如 `GDEW029Z10`、`GDEY029Z94`）
2. **挨个试**：这三个类名覆盖了 2.9 寸三色的绝大多数批次，试错很快——
   `GxEPD2_290c` / `GxEPD2_290_Z13c` / `GxEPD2_290_C90c`

选错的表现为：全白、全黑、花屏、或者只有一半有画面。选对的表现为：**闪一下黑白，然后稳定显示你写的字**。

> 三色屏第一次刷新会闪黑约 15 秒，这是正常的，别以为坏了。

## 第 2 关：让屏幕上出现中文

**验收标准：屏幕显示你的用户名（中文）。**

这一步需要中文字库。别自己造轮子，用现成的：

1. 库管理器安装 **U8g2_for_Adafruit_GFX**（作者 olikraus）
2. 它会带一套点阵中文字体，`u8g2_font_wqy12_t_gb2312` 是 12px 文泉驿，够用

示例骨架：

```cpp
#include <GxEPD2_3C.h>
#include <U8g2_for_Adafruit_GFX.h>

U8G2_FOR_ADAFRUIT_GFX u8g2Fonts;

void setup() {
  // ... display.init(...) 之后
  u8g2Fonts.begin(display);
  u8g2Fonts.setFont(u8g2_font_wqy12_t_gb2312);

  display.setFullWindow();
  display.firstPage();
  do {
    display.fillScreen(GxEPD_WHITE);
    u8g2Fonts.setForegroundColor(GxEPD_BLACK);
    u8g2Fonts.setCursor(10, 30);
    u8g2Fonts.print("你好，Kieran");   // 直接传 UTF-8
  } while (display.nextPage());
}
```

> 这一步只是为了验证"中文能显示"。量产时按方案书 5.5 自己做点阵子集，
> 因为这套字库体积大，而且文泉驿是 GPL 系字体，商用要单独确认。

## 第 3 关：连上你自己的服务器

**验收标准：屏幕显示你的真实 K 积分。**

这一关开始需要后端。先让 Django 出来一个最简单的接口：

```python
# apps/devices/views.py
def me(request):
    return json_ok({"ok": True, "username": "kieran", "points": 1280})
```

然后固件里用 `HTTPClient` 拉这个地址，把 `points` 画到屏幕上。

注意两件事：

1. 你的 Mac 和开发板必须在**同一个 WiFi** 下
2. 服务器地址用 `http://<你 Mac 的局域网 IP>:9000`，不要用 `127.0.0.1`——对开发板来说那是它自己

```bash
# 查你 Mac 的局域网 IP
ipconfig getifaddr en0
```

## 排查手册

| 症状 | 最可能的原因 | 动作 |
|---|---|---|
| 屏幕全白，什么都没 | BUSY 没接 / 型号选错 / VCC 没接 | 先查 BUSY 这根线，再换型号类名挨个试 |
| 屏幕全黑 | VCC 接错 / 复位脚悬空 | 断电，重新核对 VCC 和 RST |
| 花屏、条纹、错位 | 刷新期间发了新指令 / SPI 太快 | 确认每步都等 BUSY；`display.init(115200)` 降到 `9600` |
| 只画了半屏 | 型号选了一个分辨率不同的类 | 换类名 |
| 上传报错 "Connecting..." | 板子没进下载模式 | 按住 BOOT 再点上传 |
| 串口监视器全是乱码 | 波特率不对 | 改成 115200 |
| 反复重启 | USB 供电不足 | 换一个能供电的 USB 口，别用 hub |
| 屏幕亮一下就没了 | 正常，三色屏刷完就进休眠 | 不是故障 |

**最重要的一条**：出问题时先把 USB 拔了，看一眼接线，再插回去。80% 的问题在这一步就解决了。

## 安全与禁忌

- 断电接线，断电改线
- VCC 永远接 3V3
- 不要用手直接摸屏幕的 FPC 排线，折一次就可能断
- 冬天干燥时先摸一下金属物体释放静电，再碰板子
- 不要拿万用表电流档去量电压（会短路），量电压用电压档

## 卡住时怎么问我

把这三样发给我，我基本能直接定位：

1. **照片**：整块板子 + 接线，能看清 8 根线插在哪
2. **串口日志**：Arduino IDE 右上角「串口监视器」里的报错，全选复制
3. **型号**：屏幕背面的丝印，和你在代码里用的类名

描述现象时按这个句式最有效：

> 我做了 A，期望 B，实际是 C，已经试过 D。

例：*「我按方案书接了 8 根线，期望屏幕显示 Hello，实际是全白。已经换过 GxEPD2_290c 和 Z13c 两个类名，都白屏。BUSY 接的是 GPIO10。」*
