# 碎碎念

独立图文信息流 `/murmurs`，与论坛共享账号、头像、上传和站内通知。

## 体验与视觉

桌面端：轻量侧边导航 / 连续时间线 / 日历与记录灵感。
侧栏采用小字号字标与单行日期，弱化装饰；互动区只显示图标与数量，并保留无障碍名称。
发布框、帖子和空状态共用中间栏，使用细分隔线；输入区用浅色底和圆角边界区分编辑状态。
头像在左，昵称与 @账号分两行，时间与查看次数放在互动栏上方；正文和互动按钮沿头像右侧对齐。
时间按北京时间判断：当天显示「N 小时前」，跨天直接显示日期（跨年补年份），不出现「N 天前」。
手机端：时间线铺满可用宽度，「全部 / 提灯 / 我的」就近切换。
左对齐的中文系统字体，正文 15–16px、1.8 行高；内容宽度约 620px。
沿用站点白天、黑夜、毛玻璃、漫画主题的颜色和材质。
基础色取自现有站点：背景 #f5f5f7、表面 #ffffff、正文 #1d1d1f、
次要文字 #6e6e73、品牌红 #d9232e，交互蓝 #0071e3。
品牌红只突出发布和小型标记；不引入外部字体、图片或营销横幅。

技能检索中的通用落地页布局不适合内容信息流，因此只采用可访问性和轻量交互指导，
布局、字体、颜色继续遵循现有社区。页面的辨识点是「碎碎念。」字标与对话气泡，
其余空间留给真实用户内容；空状态邀请发布，不填充虚构用户或帖子。

## 首版范围

- 公开浏览，置顶优先，其余按最新顺序分页，默认展示近 7 天；支持我的、指定作者和单条分享链接。
- 单条详情页不显示发布框；打开详情会累加该条碎碎念的查看次数，信息流浏览不计入。
- 点击正文或卡片空白处可进入单条详情，互动栏也有「查看详情」链接，详情中完整展示正文并自动打开评论。点击头像、@、图片、点赞、评论展开或菜单仍执行原操作；选中文字不会误跳转。
- L2/L3 与主管理员可通过碎碎念右上角「⋯ → 置顶这条碎碎念 / 取消置顶」操作，置顶显示标记；普通作者、L1 与仅有版主身份的用户不能置顶。每次实际变更记录管理审计，重复请求不重复记录。
- 无标题、无富文本。文字最多 1000 字；图片最多 9 张，每张 5 MB。「提灯夜行」仅支持纯文字，带图片或视频会被拒绝。
- 发布框只通过「发布」按钮提交，回车用于换行；评论框仍保留回车发送。
- 编辑区初始高度 160px，随内容自动增高；「展开编辑」可展示完整长文。草稿继续按账号自动保存。
- 发帖与评论共用 Emoji 面板，在光标位置插入表情；计数和长度校验支持 Unicode。
- 作者旁和个人主页可关注/取消关注；数量公开展示，只有本人可以打开自己的关注/粉丝列表，列表支持搜索和分页。匿名访问名单返回 401，查看他人名单返回 403，管理员也不例外。
- 官方账号通过后台「用户管理 → 小 K 官方账号」指定，沿用现有账号资料，在碎碎念、评论、个人主页和 @ 候选中显示官方标识。
- 碎碎念及评论的作者旁展示其当前佩戴的成就勋章，与论坛文章、回复共用金 / 银 / 铜配色；未佩戴时不显示，发布后无需刷新即可看到。
- 指定官方账号并保存后，为现有用户（包含虚拟账号）补默认关注；新建用户和每日系统账号自动关注。初始化记录防止取消关注后被反复恢复。
- 主管理员可设置 0–10000 的目标粉丝数，通过关注关系补齐数量；优先复用已有系统账号，不足时新建不可登录的系统账号。减少目标只撤销系统维护的虚拟关注，保留真实用户及原有主动关注，不删除账号。
- 发帖与评论输入 `@` 或点击「@ 提及」，搜索关注的人；支持方向键选择、Enter 确认、Esc 关闭。
- @ 使用唯一用户名（特殊用户名使用 `@{用户名}`），不依赖可重复的昵称。正文中的 @ 可进入个人主页。
- 只有已关注且双向均未屏蔽的用户会收到 @ 通知；自己不收到提醒，重复请求不重复提醒，同一条评论的回复通知与 @ 通知合并。
- @ 通知进入具体帖子，评论通知链接携带目标评论 ID，加载其附近评论并高亮；支持返回查看全部评论。删除或屏蔽的评论不会泄露。
- 上传复用 `/api/forum/images`，发布时核验图片所属账号。
- 图片多选/粘贴、上传预览/移除/重试、相册放大和键盘切换。
- 点赞、评论（500 字）、删除本人内容，复用现有点赞/评论通知。
- 评论支持文字、纯图片或图文混合，最多 4 张图片，每张 5 MB；支持选择或粘贴 JPG、PNG、WebP、GIF。
- 评论中的 GIF 表情包保留动画，Emoji 选择器可在光标位置插入常用表情。
- 评论框聚焦后展开图片、Emoji 和发送工具；已有草稿、附件或错误时保持展开。
- 每条评论可点「回复」，输入框显示回复对象并支持取消，图片和 Emoji 同样可用。
- 回复按时间顺序显示，并标记被回复者；原评论被删除或屏蔽后不再展示其内容。
- 回复通知同时发送给碎碎念作者和被回复者，合并相同接收人，不给自己发通知，并遵守屏蔽设置。
- 评论附件支持预览、移除、上传失败重试和放大；发送失败保留文字、图片和请求标识。
- 刷新当前信息流或收起评论区后，评论草稿在本页保留；整页刷新或离开页面后不保留评论草稿。
- 发布和评论支持客户端标识去重；发布间隔 30 秒、评论间隔 5 秒。
- 草稿按账号保存在当前浏览器；请求失败保留内容和已上传图片。
- 屏蔽与取消屏蔽、举报碎碎念或评论、lv2 以上管理员审核和下线。
- 他人内容只能通过「举报 → 管理员审核 → 下线」移除；作者可删除自己的内容，管理员不能直接删除他人内容。
- 举报下线保留 7 天申诉期（`MURMUR_APPEAL_DAYS`）：被删除作者收到站内通知并可申诉，lv2 以上管理员在 `/murmurs?view=reports&mod=appeals` 复核，恢复或维持删除；举报人收到处理结果通知。
- 个人主页新增碎碎念页签，站点导航增加入口。

## 数据与运行

新领域应用 `apps.murmurs`，使用 `community_murmur*` 新表；不修改既有论坛内容。
评论附件通过 `community_murmur_comment_images` 关联既有图片，校验归属并保留顺序；
评论接口新增 `images` 数组，旧的纯文字请求保持兼容，举报审核也展示评论附件。
评论请求可增加整数 `reply_to`；响应返回回复对象的账号和简短上下文，不递归嵌套。
时间保存为 ISO 8601 字符串。软删除保留审核记录，举报下线与申诉复核写入既有治理日志。
下线时记录 `deleted_at`、`deleted_by`、`deletion_reason` 和 `appeal_deadline`，恢复时记录 `restored_at`；
申诉保存在 `community_murmur_appeals`，每个 `post:<id>` / `comment:<id>` 只允许一次申诉。
申诉接口：`GET /api/murmurs/appeals/context`、`POST /api/murmurs/appeals`；
管理员接口：`GET /api/admin/murmurs/appeals`、`POST /api/admin/murmurs/appeals/<id>/review`、
`GET /api/admin/murmurs/pending-count`。lv2+ 管理员会在头部通知铃铛和侧栏「碎碎念后台」看到待处理举报/申诉/精选投稿红点，
数量每分钟刷新，处理完当前条目后立即刷新；红点可直接进入碎碎念后台，通知面板顶部也会列出举报/申诉/精选入口与数量。
发布与评论不奖励积分。碎碎念后台入口 `/murmurs?view=reports`，仅管理员可读取。

更新后先执行 `manage.py backup_database`，再执行 `manage.py migrate --noinput`。
关注功能新增 `accounts.0005_userfollow`（`user_follows` 表，禁止重复关注/关注自己）和 `notifications.0002_alter_notification_type`；迁移后重启 Web 服务并刷新页面。
官方账号功能包含 `accounts.0006_user_is_system_generated_userfollow_is_managed_and_more` 和 `accounts.0007_mark_legacy_community_accounts`。
后者仅标记用户名匹配 `community_guest_YYYYMMDD`、邮箱为空且未验证的非管理员旧账号；不会改写已有真实账号资料。
官方设置入口 `/admin/users`，接口 `GET/POST /api/admin/community/official`，仅主管理员可读写；保存操作在同一事务中更新设置、默认关注和系统关注，失败时回滚。
首次部署后在后台选择已有官方账号（例如 `xiaok`），填写目标数量并「保存并同步」；配置不绑定环境中的固定用户 ID。
关注接口：`GET /api/users/<username>/social`、`POST/DELETE /api/users/<username>/follow`、
`GET /api/users/<username>/following`、`GET /api/users/<username>/followers`；列表接受 `q`、`after`。
`GET /api/users/mentions` 仅返回当前账号关注且未双向屏蔽的用户。
评论定位接口：`GET /api/murmurs/<id>/comments?target=<comment_id>`。
小 K AI 助手：见 [独立配置与运行说明](community-ai.md)。

## 提灯夜行栏目

「随便聊聊」和「提灯夜行」是发布时可选的频道（`Murmur.channel`：`daily` / `growth`），
不是独立页面。选「提灯夜行」发布后内容立刻出现在信息流，同时自动进入精选审核队列；
审核只决定它是否进入页面右侧的「提灯夜行」栏目，不影响发布和日常浏览。

- 发布：`POST /api/murmurs` 增加可选 `channel`（缺省 `daily`，非法值 400）；`GET /api/murmurs?channel=growth`
  过滤频道，导航「提灯夜行」和手机端「提灯」标签都使用该参数。`growth` 只能纯文字，
  携带 `images` 或 `video` 返回 400；发布框选中提灯夜行后会隐藏图片/视频入口。
- 栏目展示：右栏读取 `GET /api/murmurs/features?limit=6`，只返回已收录且未删除、未屏蔽当前浏览者的内容；
  桌面端在 1100px 以下隐藏右栏，改用「提灯」信息流；空栏目邀请投稿。
- 审核：作者投稿自动创建 `MurmurFeature`（pending / author）；lv2+ 管理员在
  `/murmurs?view=reports&mod=features`（入口「碎碎念后台」）按待审核 / 已收录 / 未通过筛选，可填写审核备注并通过或不收录。
  只有 `channel=growth` 的内容能进入栏目：日常碎碎念即使由管理员操作也返回 400，
  不会生成栏目记录；管理员直接收录时 `source=admin`，频道不变。
- 接口：`GET /api/admin/murmurs/features`、`POST /api/admin/murmurs/features/<post_id>/review`
  （`decision=approved|rejected`）、`DELETE /api/admin/murmurs/features/<post_id>`（移出栏目）。
  审核通过/未通过/移出都会给作者发站内通知；操作写入 `ForumModerationAction`
  （`content_featured` / `content_feature_rejected` / `content_unfeatured`）。
- 审核通过或移出后，右栏与审核列表立即刷新。提灯夜行帖子只在 `@用户名` 旁留一盏小灯（只跟随帖子，不跟随用户），
  不做成就徽章：已收录保留品牌色灯架，带暖色灯芯、外围光晕与轻微呼吸动画；减少动态效果时保留静态光晕。
  待审核仅作者/管理员可见、灯变暗并标注「待收录」，
  未通过同样仅作者/管理员可见、灯更暗并标注「未收录」。
- 右栏是无框的编辑式单条展示，每 5 秒淡入切换下一条，底部小圆点可手动选看；
  悬停或聚焦时暂停轮播，`prefers-reduced-motion` 下不自动切换。重复加载（审核、移出）会重置计时器。
- 数据：`murmurs.0011_murmur_channel_feature` 为 `community_murmurs` 增加 `channel` 字段和索引，
  并新建 `community_murmur_features`（一条帖子最多一条栏目记录，删除帖子级联删除）。
  迁移前照常先备份 `data/homepage.db`。

## 展示热度

碎碎念与论坛共用同一套「确定性热度曲线」：信息流和详情里显示的浏览/赞可以比真实值大，
但真实值永远独立存在，不写假数据、不影响热度排序、榜单、通知和后台数据大屏。

- 展示浏览 = max(真实浏览, round(目标浏览 × 进度(已过时间) × 抖动(帖子 ID)))；
  展示赞 = max(真实赞, round(min(目标赞, 展示浏览 × 8%) × 抖动))。抖动按帖子 ID 哈希到 0.90–1.10，
  同一帖子刷新/重启不变；进度按成长天数增长，到点约 95% 后持平。
- 曲线只涨不落：成长到目标值后一直保持，帖子变旧也不会回落。「停用（保留数字）」和关掉总开关都只是停止加热、把展示值冻结在当时的数值；只有显式点「停止并恢复数字」才会回落到真实值（即使总开关开着也显示真实数字），操作前会二次确认，且不会删除单帖记录。
- 全局开关与默认值在后台「系统设置 → 社区展示热度」（lv3 / 主管理员）：总开关、默认目标浏览、
  默认成长天数、默认点赞率、新帖安静期、单帖浏览上限。关掉总开关同样停止加热、数字冻结在关闭时，
  重新打开后从冻结处继续成长；卡片上的红色「停止并恢复数字」（二次确认）才会让未单独设置的
  帖子回到真实值。
- 单帖设置：碎碎念卡片「⋯ → 设置展示热度」、论坛详情页「设置热度」，可填目标浏览、几天涨到、
  目标赞数、备注，保存前有「现在 / 1 天后 / N 天后」预览；底部有「停用（保留数字）」和红色的
  「停止并恢复数字」（二次确认后带回真实值）。
- 约束：赞 ≤ 展示浏览的 8%；单帖浏览 ≤ 5000；新帖安静期内显示真实值；调低目标需二次确认；
  同一作者同一天多条贴子同时加热时后台给出提示。单帖配置存 `murmur_display_overrides` /
  `forum_display_overrides`，不改帖子表和点赞表。
- 接口：`GET/POST /api/admin/murmurs/heat/settings`、`GET /api/admin/murmurs/heat/posts?q=`、
  `GET /api/admin/murmurs/heat/overrides?q=`（已设列表，按更新时间倒序）、
  `GET/POST/DELETE /api/admin/murmurs/<id>/heat`；论坛对应 `/api/admin/forum/heat/settings`、
  `/api/admin/forum/heat/posts`、`/api/admin/forum/heat/overrides`、`/api/admin/forum/topics/<id>/heat`。
  仅 lv3 / 主管理员可访问。后台「系统设置 → 社区展示热度」下方有合并的「已设展示热度」列表，
  支持筛选、直接修改和停用。
- 部署：`manage.py migrate --noinput` 应用 `murmurs.0009_murmurdisplayoverride` 与
  `forum.0011_forumdisplayoverride`；不改帖子/点赞数据。

验证：`manage.py test apps.murmurs apps.accounts apps.notifications`、`manage.py check`、
`manage.py makemigrations --check --dry-run`。
