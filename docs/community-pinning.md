# 社区内容置顶

论坛与碎碎念的置顶均由 L2、L3 或主管理员管理。普通作者、L1 管理员和仅有版主身份的用户不能置顶。

- 论坛：打开帖子，在详情顶部操作区选择「置顶 / 取消置顶」。首页与论坛列表同步生效，详情显示「置顶」标记。
- 碎碎念：点击内容右上角「⋯」，选择「置顶这条碎碎念 / 取消置顶」。单条分享页也可以操作。
- 操作即时生效，取消后恢复正常排序；不会修改发布时间、积分、加热时长或发送通知。
- 不强制限制条数，运营建议保持 1–3 条。删除的内容不会公开显示，也不能通过置顶接口恢复。

## 排序与分页

论坛各列表在当前分类、关键词和视图筛选范围内置顶优先，热门和加热视图仍按热度排列其余内容。精华与加热视图不会混入不符合条件的置顶帖。

碎碎念在当前作者、我的和屏蔽过滤范围内置顶优先，同组按 ID 倒序。分页仍返回 `items` 和 `next_cursor`。客户端须原样回传游标：普通内容沿用数字游标，置顶分组尚未遍历完时返回 `p:<id>`，避免旧置顶内容导致跳过较新的普通内容。

## 接口与权限

`POST /api/forum/topics/<id>/pin` 与 `POST /api/murmurs/<id>/pin` 均接受严格布尔值 `{"pinned": true}` 或 `{"pinned": false}`，返回实际置顶状态。支持现有前台账号及后台管理员会话，服务端检查 L2 权限与 CSRF。

状态更新和 `forum_moderation_actions` 审计写入在同一事务内完成。重复提交同一状态不会新增日志。不存在或已删除的目标返回 404。

## 本地与部署

碎碎念新增 `0005_murmur_pinning` 迁移及信息流索引。部署前先使用 `manage.py backup_database` 备份，再执行 `manage.py migrate`，重启 Web 以加载接口和新模型。论坛沿用已有 `is_pinned` 字段。

验证：`manage.py test apps.forum.test_pinning apps.forum.tests apps.murmurs --noinput`。
