# 心映 · 动漫人格探索

心映使用独立题库、站内作答、确定性计分和 AI 人格解读，可按需补充访谈。完整新测评必须使用 AI，开始前检查服务并取得用户授权。不是官方 MBTI 量表，不提供医学、能力或人格等级判断。动漫角色是基于已审核资料的共鸣解读。

## 入口与启动

- `/personality`：产品入口与本人的历史记录。
- `/personality/test`：开始 / 继续测评；使用现有账号登录。
- `/personality/report/<uuid>`：仅本人可读的人格档案。
- `/personality/analysis/<uuid>`：本人查看实际 AI 请求、返回、用量与任务进度。
- `/admin/personality`：L3 及以上角色库管理、角色采集筛选和数据包导入导出。
- `/admin/personality/settings`：独立的 AI 模型服务页；密钥与模型连接仅主管理员可改。采集筛选保存在角色库页，L3 可管理，两者分别保存。
- `/admin/personality/analysis`：主管理员按用户名或档案编号查看分析记录；普通管理员不可读取作答与调用内容。
- `/admin/personality/operations`：主管理员查看开放前自检、异常任务和题目理解反馈；主后台与心映导航显示未处理数量。
- 全站“产品”菜单、个人中心和管理后台已增加入口。

常规 Windows 启动仍用 `start_homepage.bat`，Linux 用 `start.sh`，两者都会启动心映 worker。手动启动：

```powershell
.\.venv\Scripts\python.exe manage.py backup_database
.\.venv\Scripts\python.exe manage.py migrate --noinput
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:9000 --noreload
# 另开一个终端：
.\.venv\Scripts\python.exe manage.py process_personality_jobs --interval 2
```

首次空数据库可直接 migrate；有数据库必须先备份。生产服务器使用现有 WSGI 服务和独立心映 worker，部署前执行 collectstatic。

## 首次配置顺序

1. 主管理员在心映后台填写独立的 API 地址、模型、密钥与每人每日报告上限，点击“保存并检查连接”。复制其它服务配置的按钮已移除。下方列表展示当前生效配置、密钥是否设置、保存时间、最近检查时间与连接结果；“已保存”与“连接通过”分别显示。检查结果保存在服务端，刷新保留；连接参数变化使旧检查失效，未保存表单的试连不会认证另一个已保存连接。列表的重新检查只使用已保存配置。空密钥保留原值，清除需单独勾选。
   高级设置折叠收纳超时、输出上限、token 参数和“允许创建新测评（全站）”。全站开关用于维护时禁止新建测评，已有档案不受影响；每人每日上限限制首次提交的报告，同一份失败报告重试不重复计次。读取模型列表仍可单独使用。
2. 导入近期热门与经典候选。Bangumi 公开资料不需要用户的动漫偏好或个人回答。
3. 为候选单独或批量生成 AI 人格草稿（每批最多 40 个，不覆盖已审核内容）；补充不足的剧情证据，核对六维等级、逐字引文和理由。
4. 选择主题与图片布局；较早年代的角色需明确勾选“经典保留”；确认后通过审核。
5. 只有已审核、年代符合范围或已经典保留的角色可参与匹配。启动脚本会安装随代码发布的首批 5 个有来源依据的角色（鸣人、影山茂夫、山田凉、喜多郁代、中野梓），保留已有审核、排除和编辑内容。其余采集候选仍需依据审核；不使用夏目演示数据填补。资料标注是可追溯的编辑判断，不代表科学测量。

首批数据位于 `apps/personality/data/starter-characters.json`，可以通过 `manage.py seed_personality_catalog` 独立初始化。首页展示来自已审核库的角色图片，不展示或预判当前用户的匹配结果。图片经固定域名验证后缓存到 `data/personality-images/`；私密报告图片仍需本人登录。

历史完整报告如果没有角色，首屏上方提示原因，可点击“补全角色共鸣”。程序只添加角色、主题和对应审计依据，不重新作答、不修改原类型、计分、报告段落和原话。已有角色的报告不会重新排名。无 AI 的补全不消耗报告额度；需调用 AI 的补全遵循原有授权与每日限额。报告显示“量表解读”或“AI 深度解读”，不会把未授权的旧报告自动升级为 AI 分析。

未开启 AI、地址/模型/密钥不完整、密钥不能解密，或当前配置没有通过已保存的连接检查时，禁止新建测评并提前提示服务未就绪。开始按钮须在用户勾选 AI 分析授权后才可用，后端独立校验。配置检查绑定连接指纹，修改连接参数后须重新检查；调整报告上限不使连接检查失效。可用性查询不缓存，不在每道题保存时请求外部模型。未授权不会发送作答，当前无积分收费。

已开始测评的答案保存不依赖外部 AI。提交报告前、worker 执行前再次校验服务，服务异常保留答案与合格分析检查点，不发布规则降级报告。提交前发现服务不可用不排队、不占次数；已排队后失败的报告重试沿用原有预约次数，即使隔日也不重复扣减。新测评仍受每天首次报告上限约束，删除记录不返还限额。

历史未授权的未完成测评可在继续页面明确同意后原地续答；旧失败任务可在报告页勾选授权后使用原答案重试。旧排队任务的 ai=False 不再导致静默规则报告：已授权者按当前可用服务进行 AI 分析，未授权者暂停并提示补授权。已有完成报告保持原快照，不批量改写、不自动补授权。本次不新增数据库字段；部署后须重启 Web 和 process_personality_jobs worker。

AI 必需流程相关心映回归 173 项通过，浏览器验证未配置禁用开始、授权后开始、服务断开仍能保存与刷新续答、旧记录补授权、追问恢复、旧失败报告重试及四种视口，无脚本错误。连接检查使用已保存结果，以上回归没有调用真实外部模型。

## 运行提醒与题目反馈

“运行与反馈”汇总新测评入口、保存的 AI 连接检查、worker 近期心跳和已发布完整六维角色档案。角色数量实际校验档案，不将空白或无效档案算作可用；该页提供完整服务条件的检查结果，不会因刷新而调用模型，也不会替管理员修改开放开关。只有主管理员可查看和处理。

报告排队超过三分钟，或某阶段无进展超过 max(五分钟, 两次接口超时加一分钟)，记为等待较久。用户收到“回答已保存，不用重做，可以稍后回来”，只有运行提醒确实落库时才显示已反馈后台。任务失败也记录提醒，具体诊断留在私密分析记录里。提醒按任务去重；标记已知悉不取消或重试任务，任务进展恢复、重新排队或完成后归档。worker 每分钟巡检；后台摘要和运行页面也能发现停机积压，不依赖用户一直刷新。页面可见时运行页每十五秒刷新，导航每三十秒检查未处理数量；后台失败任务较多时按最近任务逐批展示。

正常完整报告成功后，沿用站内 system 通知，只给本人发送一次，链接直达私密报告；不广播类型、角色或作答，不为补心声重复通知。通知保存失败不使完整报告回滚，记录待补发状态，后续巡检补发而不重新调用模型。删除测评时清空相应通知链接，反馈和运行提醒跟随测评删除。该功能不回溯补发旧报告通知。

答题页每道题提供“这题没看懂”。请求只包含题目 ID，服务端从本次测评保存的题面取得版本与文字，不收集作答；同一次测评同一道题只能记录一条，刷新后保持已反馈。后台按版本、编号和实际题面合并，动态追问不混为同一道题；旧追问里嵌入的个人引文不会复制到反馈面板。管理员标记已处理后归档，原题与已保存答案不会因此被改写。

迁移 0011 新增 question feedback 与 operational alerts 两张表，沿用现有站内通知表。部署前先备份数据库，再 migrate 并重启 Web 与心映 worker。相关心映及通知回归共 200 项通过，浏览器覆盖四种宽度、后台已知悉/已处理、题面文本转义、反馈后继续作答与刷新、等待提示和完成通知说明，以及主后台计数与权限隐藏；未调用外部 AI，未在正式用户数据上模拟失败或发送测试通知。

## 测评状态与计分

- 新测评使用 `xinying-5`：四轴 64 条、六维 72 条量表候选，另有 16 条辨别、45 条情境和 12 条前置开放候选，共 209 条原创固定题目，另有回答追问模板。每次按维度、正反向和测量侧面抽取 48 道量表题，优先避开本人上一份测评用过的题。第一轮与第四轮各穿插一道开放题；最模糊的两轴各从四条辨别候选中选三条，仍共六条。根据边界、执行与发散回答分支选择三条情境题，再决定是否追问，通常合计 59～61 题，不因扩充题库增加单次答题负担。
- 题目选择与顺序在建立测评时保存；刷新不会重新抽题，回退修改不会把原有开放回答绑定到新问题。已有记录继续保留原题，新探索才使用新版抽题。基础情境和补充问题均由程序从题库选择，答题期间不调用模型。
- 常规量表轮为 8 题，穿插开放题的轮次为 9 题，辨别轮 6 题；界面一次聚焦一题。开放轮为 3 题，补充理解为 0～2 题。
- 每题保存 `value`、原文 `note`、`skipped`。量表题必须选择 1～7 分，可补充情境说明；开放情境题保留跳过选项。历史跳过记录仍按缺失值处理，不改写已有报告。
- 反向题 `8-value`；指数 `(平均分-1)/6*100`。四轴至少 4 个有效回答，扩展维度至少 3 个，否则留空；缺失值不当作零或中立。
- 四轴类型按与两端偏好的距离确定，同时保留相邻候选；距离不是概率。接近中点的维度明确保留分歧。
- AI 在一次响应中完成人格十主题、价值与心理机制、成长建议、MBTI 鉴别和匿名角色对照。每段判断必须引用有效 question_id；证据不足的主题保留不确定性。可以在程序给出的三个候选内重新排列，需给出支持与反对证据；不修改四轴和六维计分，不添加新数字或概率。收藏原话必须逐字存在，选项提炼与原话分开标注。
- 用户主动提及的动漫、角色喜好仅在分析输入中去除，原始作答保持不变。角色对照阶段隐藏姓名、作品、图片和热度；不向模型发送账号身份。
- 问卷与实际题目顺序保存在测评记录内。并发编辑使用 revision，冲突返回 409，不覆盖另一个页面的回答。
- 状态：active → ready → queued → processing → completed；失败保留回答，可重试。完成档案是固定快照，角色库修改不追溯改排名。
- 当前正常仅一次综合请求，详见下方 single-report-v1。旧任务已有 persona_parts/persona/pool/match 私密检查点时继续原来的分批恢复，避免丢弃已生成内容；旧任务尚未调用分析时也采用新流程。完成后清理任务 checkpoint，保留报告内的审计依据，管理员任务列表不展示回答或 checkpoint。
- SQLite 提交先做条件写入再检查任务和配额，避免并发读事务升级锁；重复提交不会重复排队或计次。同一份失败报告重试沿用次数，删除档案不能重置限额。worker 上报心跳，后台显示运行状态；中断任务超过 15 分钟后转为可重试。

## 一次综合生成与费用控制（single-report-v1）

答题阶段使用题库、四轴模糊程度、同侧面答案差异与原题关联选择补充题，不调用模型，不建立新的 followup 任务。旧排队中的追问在处理时改为同主题题库回退，保留已有题面及答案；原有付费分批报告检查点继续沿用。无需新增后台配置字段或数据库迁移。

`single_report.py` 在调用前准备真实作答、程序分数、三个类型候选和最多六个角色候选。角色先按六维距离筛选，并保留部分标签差异；AI 在综合请求中根据真实行为和原因作最终选择。角色姓名、作品、图片、热度不发送，少量完整证据去重后发送；引用只能来自实际发送的资料，不能引用隐藏的全文。用户回答仅发送一次，空白补充和重复状态字段不发送；补充文字合计最多六千字符，保留整段或明确标为未读取，不截断转折。纯文字回答若因预算未发送，不作为可引用证据；原始数据始终保留。

模型一次返回全部十主题、名称总结、成长建议、机制、三个 MBTI 候选鉴别、可选心声与一个角色对照，网页与图表由程序组装。主题建议五十至九十字，减少重复；单次输出上限为管理员上限与六千 token 中较小值，原设置为零时本流程使用六千。DeepSeek 官方综合报告采用非思考 JSON 输出，其它服务不发送专属思考参数。

正常一次请求。返回字段逐项验证并保存：某主题或角色对照不合格时，仅请求缺失部分，不覆盖已通过内容。单个后台任务最多两次物理完成请求：一次生成、最多一次修复；截断/无效 JSON 允许一次简洁重试，网络超时、鉴权或模型配置错误停止，不暗中重发。此流程关闭传输层额外的 token 参数兼容重试和截断重试，避免绕过预算；服务不接受当前 token 参数时需在高级设置修正，不能自动移除输出上限。

自动修复仍不合格则暂停，保留回答、合格部分和当日报告额度。用户主动重试开启该新任务的请求预算，只补待处理部分；不保证跨所有主动重试永远只收费一次。候选资料修订、撤回时使相应角色结果失效，但保留可沿用的人格内容。实际物理请求与服务返回的 token usage 沿用分析过程记录；报告审计记录累计逻辑请求和最后输入字符数，字符数不冒充 token 或金额。合并减少重复输入，不预先声称固定节省比例。

相关心映与通知回归 231 项通过，另复核 15 项一次生成专项，包括旧空检查点升级、旧追问回退、付费分批结果沿用、网络失败不重发、最多一次字段修复及角色撤回检查。真实本地 HTTP 兼容服务验证一次完成请求、十主题和角色报告、usage 写入；模拟用量仅用于检查记账，不作为实际费用估算。隔离浏览器走通 60 题（含一道题库补充），覆盖四种宽度、键盘、刷新和可选文字，无脚本错误；未调用付费外部模型。

## 场景与测量目标修订（xinying-5）

当前题库在 `apps/personality/situated_bank.py`，完整的 209 条题目、计分方向、测量侧面及可能干扰见 [personality-question-review-v5.md](personality-question-review-v5.md)。每条量表独立声明 reverse 和 facet，不再由旧题面的数组位置隐式继承其含义。原有四轴及六维公式不变；重要侧面在抽样时保留覆盖，追问只对照同一侧面，避免沿用旧题编号推断新版题意。

本轮去掉先想再答→内向、消费实用性→T、社交主动追问→共情等混杂写法。四轴强调恢复/陪伴偏好、信息切入点、决策依据与安排偏好；启动和坚持留在执行维度。情绪敏感聚焦日常刺激的反应强度，恢复关注日常小事后的缓和与重新投入，不用创伤、大事件或无条件坚持制造高低差异。每题聚焦一个主要回答点，避开抽象术语、道德优劣和动漫偏好。

前置开放题、分支情境、模板追问与 AI 追问一起审阅。新版保存测量侧面以便接住原题；AI 仍只澄清真实回答，不额外生成分数。旧 v3/v4 记录未问到的后续轮也继续从原版本题库选择；已保存的题面、答案和完成报告不改写。新增题面及侧面属于新的探索版本，不将跨版本分差当作人格变化。

旧 v4 题面在 plain_bank、v3 在 scenario_bank 保持冻结，旧无版本快照继续使用原题库。当前固定题库扩充到 209 条，单次题量与 AI 调用轮数维持原流程。内容审阅、结构检查、计分和兼容性回归不等同于心理测量学验证，不据此宣传准确率。

本轮心映与通知回归共 208 项通过；另检查 120 组抽题种子的方向平衡与侧面覆盖。隔离浏览器完整走通 59 道固定题，确认刷新后题面和答案保留，并检查 320/390/768/1440 像素下无横向溢出或脚本错误。测试不调用真实外部模型，不修改正式测评记录；准确性仍需后续用户反馈与独立验证。

## 只点选也能完成（choice-v1）

新建测评在首轮快照保存 `response_policy=choice-v1`。量表仍为 1～7 分；原有 57 条定性题候选在 `choice_answers.py` 各配四项情境回答，以及“要看情况／暂时无法判断”和“都不太符合，我想自己说”。每题仍可展开自愿补充；只有主动选“自己说”时需要写一个简短想法，也可改选其它项继续。固定题量不变，不要求人人写文字。

选项快照跟题面一起保存。API 在原有 `value/note/skipped` 之外新增 `choice` ID，验证 ID 必须存在于该题快照，忽略客户端自传选项文案；`note` 只存真实手写内容。旧客户端提交完整文字仍作为自述保存。选择题保留内部 `kind=open` 以兼容历史流程，但不设置量表 target，不参与数值计分。

AI 分析会收到经过快照解析的 `selection={id,text}`，与 `note` 分开理解；“无法判断”且没有补充时不作为明确证据。追问可以基于选择继续澄清，必须输出三至五个相应选项；系统补上两个兜底项。选项缺失、重复、偏离范围或依据不合法时回退到同主题可点选模板，不退回必填文字。没有足够资料可结束追问，不能为了凑轮数制造问题。

没有可提炼的原话时，心声可基于一条明确选择生成，记录 `origin=ai_from_choices`、题目 ID、选项 ID 与原选项，展示为“属于你的一句话”，不冒充用户亲口说过的话；不可靠时留空。保存前照常允许编辑或隐藏。报告回答依据、原始作答导出和打印同时显示所选项及自愿补充。

该策略仅作用于新快照；已有题面、原答案与报告不被批量改写，旧版本继续按原方式作答，也仍可跳过开放题。不需要数据库结构迁移。

相关回归共 216 项通过，包含全程无手写文字、两轮可点选追问、AI 报告及角色匹配的完整数据流。“自己说”空白校验、“无法判断”不冒充明确证据、选项 ID 与快照校验、原话与选项落款来源均有覆盖。隔离浏览器走通 59 道固定题，并验证四种宽度、键盘选择、刷新恢复、补充文字保留、报告依据、原始答案导出及落款隐藏/编辑。模型调用使用模拟服务，验证数据流而非真实模型输出质量。

## 历史题面修订（xinying-4）

v4 固定题库 143 条逐条改为日常用语，开放题聚焦一个主要回答点。历史审阅清单见 [personality-question-review-v4.md](personality-question-review-v4.md)。v4 测评使用 plain_bank；v3 测评继续使用 scenario_bank，已保存的题面与回答不重写。计分目标、正反向映射及公式保持不变，语言改写不代表完成了心理测量效度验证。

模板追问从原题的 focus/target 确定主题，不再靠“需要、朋友、感受”等散词猜测。原话单独展示，并可展开原题。仅在同一问题方向、确有明显不同的原始选择且可比较的题目之间提供对照，展示两道具体原题及真实选择；交流恢复与边说边想等不同侧面不混比。不把正常差异称为矛盾，没有合适证据时不凑第二问。

AI 请求固定本轮 anchor（原题、完整回答、主题），第二轮优先接住第一轮回答；返回的引文来源和主题必须与 anchor 一致。提示要求简短具体、避免抽象套话及跨话题推断。引文和主题校验不能单独证明语意合理，仍需持续检查实际题面与用户反馈。

相关回归共 252 项通过，另复核 7 项题面/追问专项。隔离浏览器验证投入类原话不会套用关系问题、实际题目与原始选择对照、四种视口，以及两轮 AI 追问到完整角色报告的流程。测试使用本地兼容接口，没有为本轮验证调用真实外部模型。

## 角色发现、证据与审核

数据源：[Bangumi 公开 API](https://bangumi.github.io/api/)。只调用固定 API 主机和已知角色图片 CDN。资料为社区提供，必须校验，不能把接口当作官方人格数据库。

- 作品按 `heat` 排序，并以收藏人数过滤；近期按年份筛选，排除尚未播出的日期。
- 经典候选按年代分组取热门作品，管理员确认后形成保留名单。
- 优先主角；重要配角需要更高的角色收藏数。作品收藏、角色收藏、每作品数量可配置。
- 仅手动触发采集，不配置定时任务。作品搜索按 20 条分页，每个年代段最多 10 页；已经完整扫描的作品在当前季度、相同筛选条件下跳过，继续寻找后续作品。作品数量是本批检查的新作品上限，角色数量是本批新增上限，不保证每次都填满。
- 按 Bangumi 角色 ID 持久去重，不同季度、续作不会重复获取已收录角色详情。`CharacterDiscovery` 同时保存已过滤、采集失败的 ID；已排除角色也保留，重新采集不会恢复或覆盖。只有勾选“同时重试以前采集失败的详情”才重试失败记录，已过滤记录仍跳过。`CharacterWorkScan` 保存作品扫描进度；每作品上限只计本次新增角色，已有角色不占额度。
- 初选：采集默认只创建 candidate，本页默认全选，可取消勾选或点 × 排除，再点击“生成人格档案并复核”。取消勾选在同一浏览器会话内按管理员保存，× 排除持久保存并可恢复；支持撤销刚才的排除。每批最多生成 40 个角色，不自动处理其余候选。
- 生成与 AI 依据复核在同一个后台任务内连续执行，无需中间再点击。第二次模型调用核对角色身份和六维判断的来源支持情况；程序校验引用确实存在于提供的原文中。资料缺失保持空缺，复核异常不会发布。此复核针对已有来源的一致性，不能保证来源本身正确，也不代替科学人格测量。
- 发布：合格档案默认勾选，异常和暂缓项默认不选。管理员可批量通过、× 暂不发布、恢复待发布、不收录，或填写问题后重新生成。仅重新复核沿用已有档案；调用失败可“继续处理”，已生成草稿保存在 checkpoint 中，不重复生成。高级编辑仍可补充来源、人工确认依据并发布，记录人工确认信息。
- revision 与来源/档案指纹防止旧任务覆盖后续人工修改；资料变更使原 AI 复核失效。重复点击不会重复排队，发布必须使用当前版本、完整档案与有效复核结果。AI 生成与复核完成只形成 draft，不会自动进入可匹配库。
- 额外资料以“来源 HTTPS 链接＋原文”保存（最多 12 个补充来源，不含 Bangumi 基础资料）。程序不会访问管理员填写的补充链接。
- 自动补证据：高级设置中默认开启。使用 `https://api.deepseek.com` 官方文本接口时复用主密钥；其它文本服务需单独填写 DeepSeek 搜索密钥，独立加密保存。密钥只发送至固定官方 Search/Fetch API，不发给搜索结果网站。搜索接口配置就绪不代表账户一定有搜索权限，实际错误保存在角色处理说明中。
- 首次生成或复核发现六维依据不足时，每轮按角色名、作品和缺失维度最多搜索两次，必要时最多读取三个网页；每任务最多三轮定向补充（最多六次搜索、九次网页读取）；只接纳身份一致的实际正文，优先权威来源和已知百科，排除 MBTI 标签页面，不将摘要、模型记忆或默认中点当证据。每次最多新增三个来源，补充来源总数不超过十二个。针对问题维度修正及复核，仍不足则暂缓，不自动发布。
- 原文进入 `extra_sources`，随角色数据包迁移；成功搜索结果本地缓存 30 天，空结果与失败缓存一天，避免重复调用。更换搜索凭据后重新尝试。缓存本身不随数据包导出，迁移后仍保留已使用的来源原文。搜索只使用角色身份与缺失维度，不发送用户作答。来源冲突仍由复核拦截；网页可用性、语种和角色别名会影响补证据结果。
- 新生成提示明确 summary/mechanism 的字符串类型及长度；兼容旧机制对象时仅展开已有文字，不填补六维数值。格式异常、资料不足、依据需核对、接口/任务异常分别标示。仅重新复核不触发搜索或重生成；资料不足可选择“重新生成”，自动尝试补证据。补证据来源和生成草稿写入 checkpoint，后续调用失败可继续；人工改动 revision 后，旧任务不会覆盖。
- 六维标注是 1～7 的编辑刻度。每维必须有逐字来源引文和解释；无法支持时 level=null，维持草稿。审核是编辑判断，不代表量表效度验证。
- 开启且授权 AI 时：在有效已审核角色中结合六维距离与有引文支持的机制标签筛出最多 12 个候选，匿名比较动机。结果必须有双方证据、相似点及明显不同点，只允许选择候选池内的角色。候选顺序按测评 ID 固定打散，重试顺序一致；不按性别、热度、用户动漫喜好或四字母角色标签加权。未授权或未开启 AI 时采用六维平均绝对差规则匹配。
- 轮廓接近指数 `100-mean(abs(user[i]-character[i]))`，不代表科学相似概率。角色原始等级、引文、理由、资料链接及审核时间保存在报告审计数据中。

## 六维证据先行（six-evidence-2）

输出长度控制：角色生成提示要求简洁的简介、机制和逐维理由，定向修正仅返回问题维度，程序合并保留其余内容。用户人格解读覆盖全部十个主题，每段约一百至一百八十字，成长、类型鉴别与机制理由分别限制篇幅，并优先引用最相关的少量题目 ID；角色对照只展开最终选择，不重复分析全部候选。

针对 DeepSeek 官方角色生成/复核、用户人格解读和匿名角色对照请求，明确使用低强度思考与 JSON 输出，避免沿用服务默认的高强度思考。若 finish_reason=length，仅在同一次调用流程内再尝试一次非思考的完整简洁输出，保持管理员配置的 token 上限不变；不拼接截断 JSON，不省略必需主题和证据。第二次仍截断则停止，原始回答与已通过的分析检查点保留，允许用户重试。自动补试属于原后台任务，不另计一次站内报告额度；用户手动重新提交仍遵循既有每日限额。其它兼容服务及无明确分析用途标记的请求保持原传输策略，不发送 DeepSeek 专属参数。后台输出上限不会被自动提高。

新建/重新生成的角色任务先按原文整理六维证据候选表，再进行评分。候选按相关词和角色上下文检索，逐字保留来源片段，不代表程序已证明该维度成立，也不会自动分配分数。证据候选稀缺时先补来源，再调用生成模型。

生成与审核共用 `character_rubric.py` 的定义、低高倾向描述和分级指导，允许明确性格描写、具体剧情行为与有依据的综合推理；每项写明事实→心理机制→限定情境的编辑倾向。单次明确事件可以支持限定判断，不要求原文包含心理学术语、1–7 分或达到实证研究标准。未知仍为空，不能用中点补全。每维可保存最多三段额外逐字引文 supporting_quotes，程序逐段校验。

审核认可的维度在任务内及后续重新生成任务之间保留。仅对未认可项定向补证据或使用已有事实修正解释，生成器不能改写锁定分数；真实反证可重新打开已认可项，反证也必须逐字存在。最多三轮，仍不足或身份/版本不一致则保留待处理。发布继续要求六维完整、引用有效、独立复核通过。只重新复核不会生成或搜索。

每轮来源、草稿、待修维度、锁定结果与预算写入检查点；中断后沿用已保存步骤。历史失败任务点击继续处理会升级新流程并复用已有草稿，原有进行中任务兼容旧检查点。新流程的后台详情可展开六维证据与判定，任务进度显示整理证据、联网补证据、修正问题维度等阶段。

首批五份是预置编辑档案，由启动数据包直接发布，未经历独立 AI 复核。它们的事实→机制→有限情境推断方式是新规则的参考，不构成自动审核正确率基准。后台以“已发布 · 预置编辑”明确区分，现有报告与发布记录不被批量改写。

## 证据获取与引用优化（evidence-search-4）

- 取消“同域名只收一篇”的硬限制。不同词条或剧情页可以补充，电脑版/手机版和跟踪参数归并；正文高度重合才去重。较长正文增加新事实时不因包含旧简介而被整体排除。可信来源筛选、固定搜索服务、公开 HTTPS 地址检查和调用次数上限保留。
- 六维证据候选使用稳定的 ev_ 编号，编号由来源 URL 和逐字片段生成。生成模型返回 evidence_id、可选 supporting_evidence_ids，复核返回 source_evidence_id；程序从当前角色的原文片段取回引文。编号错误、过期、跨角色，或手改文本与编号不一致时拦截。旧版逐字引文与人工编辑仍兼容，评分和发布条件保持不变。
- 发散思考同时检索比较方案、改变办法、调整策略，以及明确拒绝其他方案、在办法失败后僵化重复等行为。反向行为可支持较低倾向；没有相关描写或仅坚持同一目标不能当作低分。三轮使用不同检索表达，保持最多六次搜索和九次网页读取。
- 新采集记录在 source_stats.identity 中保留 Bangumi 的原名、中文名和别名，以及作品其他名称。历史角色首次补证据时最多补取两条固定 Bangumi 元数据，保存后复用，失败一天后再试；角色与作品须同时匹配，短英文名检查单词边界。先检查完整正文中的身份，再选择角色相关的连续原文窗口。缓存键含别名与检索版本，旧空结果不阻挡新别名检索，保存过滤原因计数便于排查。
- 管理页遇到 401 显示中文提示与带返回地址的重新登录链接，停用写入按钮并停止轮询。保持本浏览器按管理员保存的勾选，重新登录后恢复；不自动重放发布请求，不放宽后端 require_admin / CSRF。可发布是内容状态，登录有效是操作的独立前提。

## 扩展来源与跨任务保留

- 来源池上限统一为 12 份补充原文，采集、后台编辑、数据包导入导出采用同一上限。它是资料数量预算，独立于单次输出 token 上限；不会提高管理员配置的输出上限。
- 单次生成或复核从资料池按待修维度选取 3～5 个来源；不足三份时使用已有来源，不虚构补足。正文仅传逐字片段，含身份摘录合计最多 9000 字符；证据候选引用编号，避免重复传整篇资料。所有原文仍完整保存在角色资料池。
- 自动补充最多三轮；达到六维要求立即结束。没有新资料且修正后没有进展时提前停止，保留草稿和已认可维度，不必耗尽轮次。来源池已满、接口关闭或没有结果时也不强行搜索。达到轮次上限并不表示 token 额度耗尽。
- 每项认可记录绑定人物及作品身份、规则版本、维度内容、复核引文、实际用到的来源正文摘要。新增无关来源保留原认可；修改分数、理由、身份或已引用来源时使相应认可失效。明确反证可解除锁定，失败任务也保留已保存的认可记录。未改变资料的完整合格档案再次提交可直接复用有效复核。
- 某维没有分数或有效引文时，先独立复核其他有效维度，后续只修复未认可项；六维仍需全部有效才能批量发布。新增资料后需要复核当前档案，不自动发布。后台任务显示沿用维度数，保存编辑表单会保留未修改引文的证据编号及额外支持引文。
